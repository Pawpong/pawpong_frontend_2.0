집행할 수 있는 규칙으로 변환한다.

## 1. 규칙 언어

- **필수(MUST)**: 승인을 위해 반드시 지켜야 한다.
- **금지(MUST NOT)**: 사용자가 예외를 명시적으로 승인하지 않는 한 허용하지 않는다.
- **권장(SHOULD)**: 우선 적용해야 한다. 벗어나려면 구체적인 제품 또는 접근성 사유가 필요하다.
- **허용(MAY)**: 이 문서의 다른 제약을 지키는 범위에서 선택할 수 있다.

## 2. 기준 우선순위

충돌이 발생하면 다음 순서로 판단한다.

1. 정확한 대상 Figma 노드와 현재 Dev Mode 값
2. 현재 Figma 변수와 승인된 컴포넌트 variant
3. 저장소에 이미 등록된 승인 포퐁 에셋
4. 이 브랜드 하네스
5. 로컬 구현 관례
6. 임의의 디자인 판단

대상 Figma 노드와 이 문서가 충돌하면 해당 구현에서는 Figma를 따르고 차이를
보고한다. 하네스를 조용히 다시 작성하거나 새로운 토큰을 임의로 추가하면
안 된다.

## 3. 브랜드 명제

포퐁은 다음과 같은 서비스다.

> 명확하고 신뢰할 수 있는 제품 UI와 유쾌한 픽셀 표현을 결합한 따뜻한 반려동물 서비스

모든 화면은 다음 네 가지 원칙을 필수(MUST)로 보존해야 한다.

### 3.1 명확한 사용성

- 검색, 내비게이션, 입양, 메시지 및 커뮤니티 행동은 즉시 이해할 수 있어야 한다.
- 장식용 픽셀 그래픽은 콘텐츠, 라벨, 조작 가능 요소 또는 동물 사진을 가리면 안 된다.

### 3.2 픽셀의 즐거움

- 픽셀 그래픽은 동물, 왕관, 브랜드 내비게이션, 반응 및 축하 순간에 집중하는 것을 권장한다.
- 일반 기능성 컨트롤은 픽셀 장식을 억지로 적용하는 대신 명확한 기능성 아이콘을 사용할 수 있다.

### 3.3 따뜻한 신뢰

- 포퐁 Main 브라운은 안정감과 반려동물의 따뜻한 인상을 전달한다.
- Sub 골드와 Point 옐로는 즐거움, 선택 상태 및 행동 유도를 전달한다.
- 블루는 현재 Main 브랜드 컬러가 아니다. 대상 Figma 노드가 명시적으로 사용하는 기존 화면 또는 기능 역할에서만 사용할 수 있다.
- 크림, 오렌지, 노랑, 갈색 및 분홍은 따뜻함을 더한다.
- 필수 정보에는 장식용 일러스트 색상 대신 중립 텍스트 색상을 사용해야 한다.

### 3.4 동물 우선

- 동물 사진과 동물을 식별할 수 있는 특징이 시각적 우선순위를 가져야 한다.
- 카피는 동물을 소비 가능한 상품이 아니라 평생을 함께할 반려동물로 다뤄야 한다.

## 4. 색상 시스템

### 4.1 공식 Primitive 브랜드 팔레트

현재 브랜드 팔레트는 `Main`, `Sub`, `Point`의 세 축으로 구성한다. 새 작업은
임의의 HEX 대신 아래 Primitive 또는 이를 참조하는 시맨틱 토큰을 사용해야 한다.

| 단계 | `Colors/main/*` | `Colors/sub/*` | `Colors/point/*` |
|---:|---:|---:|---:|
| 50 | `#F5EADF` | `#FEF9EF` | `#FFFFF1` |
| 100 | `#EDDBCA` | `#FDF4DF` | `#FFFFE3` |
| 200 | `#DDBE9F` | `#FBE8BE` | `#FFFFC7` |
| 300 | `#CDA073` | `#FADD9E` | `#FFFEAA` |
| 400 | `#BD8348` | `#F8D17D` | `#FFFE8E` |
| 500 | `#AD651D` | `#F6C65D` | `#FFFE72` |
| 600 | `#8A5117` | `#CDA44B` | `#DBDA5B` |
| 700 | `#683D11` | `#A48239` | `#B6B644` |
| 800 | `#45280C` | `#7B6126` | `#92912E` |
| 900 | `#231406` | `#523F14` | `#6D6D17` |

역할:

- `Main/500 #AD651D`: 주요 브랜드 텍스트·아이콘·선택 상태 및 동물 픽셀 외곽선
- `Sub/500 #F6C65D`: 동물 기본 모색과 따뜻한 보조 강조
- `Point/500 #FFFE72`: 주요 버튼과 강한 행동 유도
- 단계 변화는 같은 팔레트 안에서 상태 또는 대비를 표현할 때만 사용한다.

### 4.2 현재 등록된 시맨틱 토큰

| 역할 | 기본 | Hover | Press | Selected | Inverse |
|---|---:|---:|---:|---:|---:|
| `main color` | `#AD651D` | `#BD8348` | `#8A5117` | `#683D11` | `#FFFFFF` |
| `sub color` | `#F6C65D` | `#F8D17D` | `#CDA44B` | `#A48239` | `#FFFFFF` |
| `point color` | `#FFFE72` | `#FFFEAA` | `#DBDA5B` | `#B6B644` | `#FFFFFF` |

`Colors/bg/interactive/*`, `Colors/border/interactive/*` 역할에서 사용한다.

않고 Figma의 `main color`, `sub color`, `point color` namespace를 따른다.

### 4.3 화면 전용 및 일러스트 원시값

다음 값은 최종 디자인에 존재하지만 등록된 시맨틱 변수에 일관되게 연결돼
있지 않다. Figma에서 변수로 승격되기 전까지 표에 지정된 역할에만 사용할 수
있다.

| 값 | 승인 역할 | 제안 시맨틱 토큰 |
|---|---|---|
| `#8BA7FF` | 히어로 배너 배경 | `Colors/bg/brand/hero` |
| `#FFEABD` | 명예 동물 패널 배경 | `Colors/bg/brand/warm` |
| `#FFF8E8` | 명예 카드 및 따뜻한 크림 표면 | `Colors/bg/brand/cream` |
| `#F28A2E` | 기존 오렌지 동물 채움 | `Colors/illustration/orange/base` |
| `#C76516` | 치즈태비 무늬와 기존 오렌지 음영 | `Colors/illustration/orange/shade` |
| `#A85A13` | 짙은 갈색 디테일 | `Colors/illustration/brown/deep` |
| `#FFD84D` | 노란 털, 배 및 축하 강조 | `Colors/illustration/yellow/base` |
| `#FF8FA3` | 귀, 코, 볼 및 애정 표현 강조 | `Colors/illustration/pink/accent` |
| `#FFFFFF` | 동물 얼굴 및 픽셀 하이라이트 | 기존 inverse 토큰의 alias |

규칙:

- 새로운 UI 색상은 등록된 시맨틱 토큰에서 가져와야 한다.
- 위 원시 팔레트는 포퐁 일러스트와 승인된 따뜻한 브랜드 표면에 사용할 수 있다.
- `#8BA7FF`, `#FFEABD`, `#FFF8E8`은 해당 화면 노드의 직접 근거가 있을 때만 사용한다. 현재 Main 토큰으로 승격하지 않는다.
- 원시 일러스트 색상을 오류, 성공, 경고 또는 정보 색상으로 사용하면 안 된다.
- 새로운 표준 동물 픽셀 외곽선에는 `Main/500 #AD651D`를 사용한다.
- `#406DFF`는 새 브랜드 기본색으로 사용하지 않는다. 대상 Figma 노드가 요구하는 기존 기능 또는 화면에서만 유지한다.
- 접근성 검토 없이 `#A6A6A6`로 핵심 본문을 표현하면 안 된다.
- 오렌지, 분홍 또는 노랑만으로 상태나 의미를 전달하면 안 된다.

### 4.4 격리된 레거시 후보

다음 토큰은 현재 최종 메인 페이지 시스템이 아니라 Figma 과거 이력 영역에서 확인됐다.

| 토큰 | 값 | 충돌 |
|---|---:|---|
| `color/text/primary` | `#171717` | 현재 `#3E3E3E`와 충돌 |
| `color/bg/primary` | `#FFFFFF` | namespace 중복 |
| `color/border/teritary` | `#E5E5E5` | 오탈자이며 테두리 의미 중복 |
| `color/bg/interactive/inverse` | `#FFFFFF` | inverse namespace 중복 |
| `Secondary/700` | `#4E9CF1` | 현재 Main/Sub/Point 역할과 충돌 |
| `Alpha/Primary 80` | `#4F3B2ECC` | 현재 역할이 정의되지 않음 |
| `Colors/.../interactive/primary color/*` | 기존 블루 계열 | 현재 `main color` namespace와 충돌 |
| `Colors/.../interactive/secondary color/*` | 기존 보조 계열 | 현재 `sub color` namespace와 충돌 |

금지(MUST NOT):

- 새 작업에 격리된 토큰을 사용하지 않는다.
- 하나의 새 컴포넌트에서 `color/...`와 `Colors/...` namespace를 섞지 않는다.
- `Colors/border/error`, `Colors/text/error`, `Colors/bg/error`, `Colors/icon/error`는 현재 상태 시스템이므로 격리하지 않는다.
- 별도의 마이그레이션 검토 없이 격리된 토큰을 삭제하지 않는다.

## 5. 타이포그래피 시스템

현재 확인된 모든 텍스트 스타일은 행간 `150%`, 자간 `0`을 사용한다.

### 5.1 디스플레이 스타일

| 스타일 | 서체 | 크기 | Figma 스타일 | 용도 |
|---|---|---:|---:|---|
| `Heading/display/2xl` | Cafe24 ProUp | 40px | Bold | 히어로 헤드라인 |
| `Heading/display/xl` | Cafe24 ProUp | 32px | Bold | 큰 브랜드 제목 |
| `Heading/display/lg` | Cafe24 ProUp | 24px | Bold | 브랜드 섹션 제목 |
| `Heading/display/md` | Cafe24 ProUp | 20px | Bold | 브랜드 섹션 제목 |
| `Heading/display/sm` | Cafe24 ProUp | 16px | Bold | 픽셀 탭 및 브랜드 라벨 |
| `Heading/display/xs` | Cafe24 ProUp | 14px | Bold | 작은 브랜드 라벨 |
| `Heading/display/2xs` | Cafe24 ProUp | 12px | Bold | 최소 크기 브랜드 라벨 |

Cafe24 ProUp은 Figma 스타일명이 Bold이더라도 생성 코드에서 숫자 weight
`400`으로 해석될 수 있다. 다른 font weight를 강제로 지정하지 말고 승인된
폰트 파일과 실제 렌더링 결과를 맞춘다.

### 5.2 타이틀 스타일

| 스타일 | 서체 | 크기 | 굵기 | 용도 |
|---|---|---:|---:|---|
| `Heading/title/lg` | Pretendard | 40px | 700 | 큰 UI 제목 |
| `Heading/title/md` | Pretendard | 32px | 700 | 주요 UI 제목 |
| `Heading/title/sm` | Pretendard | 24px | 700 | 배너 부제 또는 주요 UI 제목 |
| `Heading/title/xs` | Pretendard | 20px | 700 | 표준 섹션 제목 |

확인된 부채: `Heading/title/sm`은 현재
`typography/heading/title/md/font weight` 변수를 참조한다. 새로운 토큰
시스템에서 이 교차 크기 참조를 재현하면 안 된다.

### 5.3 본문 스타일

| 스타일 | 서체 | 크기 | 굵기 | 용도 |
|---|---|---:|---:|---|
| `Body/2xlarge/*` | Pretendard | 24px | 700/600/400 | 큰 본문 및 강조 |
| `Body/xlarge/*` | Pretendard | 20px | 700/600/500/400 | 큰 UI 본문 |
| `Body/large/bold` | Pretendard | 16px | 600 | 프로필 이름 및 강조 라벨 |
| `Body/large/medium` | Pretendard | 16px | 500 | 내비게이션 및 입력 텍스트 |
| `Body/medium/bold` | Pretendard | 14px | 600 | 뱃지, 텍스트 버튼 및 카드 강조 |
| `Body/medium/medium` | Pretendard | 14px | 500 | 메타데이터 및 보조 콘텐츠 |
| `Body/small/medium` | Pretendard | 12px | 500 | 시간 및 3차 메타데이터 |
| `Body/xsmall/*` | Pretendard | 10px | 700/600/500/400 | 제한적인 최소 보조 라벨 |

`Body`의 `bolder/bold/medium/regular`는 각각 700/600/500/400을 의미한다.
단, 일부 크기에는 현재 모든 굵기의 로컬 Text Style이 존재하지 않을 수 있으므로
구현 대상 노드의 실제 스타일을 우선한다.

규칙:

- Cafe24 ProUp은 짧은 브랜드 제목과 라벨에만 사용해야 한다.
- 긴 카피, 입력창, 카드, 메타데이터 및 컨트롤에는 Pretendard를 사용해야 한다.
- 14px 이하의 긴 텍스트에 Cafe24 ProUp을 사용하면 안 된다.
- 커뮤니티 미리보기는 한 줄 말줄임을 권장한다.
- 입양 카드 설명은 Figma가 정의한 3줄 범위를 넘어가면 안 된다.

## 6. 간격 시스템

현재 등록된 간격 값:
`0 / 2 / 4 / 8 / 12 / 16 / 20 / 24 / 28 / 32 / 36 / 40 / 44 / 48px`

| 값 | 주요 역할 |
|---:|---|
| 2px | 뱃지 미세 간격 |
| 4px | 아이콘·숫자 및 컴팩트 컨트롤 간격 |
| 8px | 기본 컴포넌트 간격 |
| 12px | 입력창 및 카드 padding |
| 16px | 큰 카드의 가로 padding |
| 20px | 내비게이션 및 콘텐츠 그룹 |
| 24px | 큰 컴포넌트 내부 간격 |
| 28px | 승인된 중간 간격 |
| 32px | 강조 패널 padding |
| 36px | 큰 열 간격 |
| 40px | 표준 섹션 세로 padding |
| 44px | 큰 터치 대상 및 특수 간격 |
| 48px | 큰 섹션 또는 반응형 margin |

현재 확인된 중복 alias:

- `gap/2 = 4px`
- `padding/6 = 16px`
- `size-height/1 = 8px`
- `size-height/8 = 8px`

새 컴포넌트는 중복 primitive를 추가하지 말고 `spacing/*` 값을 사용하는 것을 권장한다.

## 7. radius 및 형태 시스템

| 토큰 | 값 | 용도 |
|---|---:|---|
| `radius/0` | 0px | 직각 형태 |
| `radius/2` | 2px | 미세 radius |
| `radius/4` | 4px | 컴팩트 컨트롤 |
| `radius/8` | 8px | 입력창, 이미지 및 표준 카드 |
| `radius/12` | 12px | 배너, 강조 패널 및 명예 카드 |
| `radius/16` | 16px | 대상 노드가 지정한 큰 표면 |
| `radius/20` | 20px | 대상 노드가 지정한 큰 표면 |
| `radius/999` | 999px | 뱃지 및 chip |

규칙:

- 완전한 pill 또는 원형에는 `radius/999`를 사용한다. 현재 등록되지 않은 `radius/max`를 새로 사용하지 않는다.
- 픽셀 아트 자체에 둥근 vector corner를 적용하면 안 된다.
- 원형 아바타는 카드 radius와 별개로 최대 radius를 사용할 수 있다.
- `radius/16`과 `radius/20`은 등록된 값이지만 대상 노드의 근거 없이 임의 적용하면 안 된다.

## 11. 아이콘 및 픽셀 에셋 시스템

### 11.1 기능성 아이콘 크기

| 컨테이너 | 용도 |
|---:|---|
| 20px | 작은 화살표 |
| 24px | 메뉴 및 더보기 |
| 32px | 헤더 내비게이션 및 커뮤니티 행동 |
| 40px | 아바타 및 왕관 패밀리 |
| 48px | 주요 하트 행동 |
| 154px | 홈 동물 캐릭터 |

### 11.2 에셋 분류

기능성 아이콘:

- 기존 디자인을 구현할 때 검색, 채팅, 메뉴, 더보기 및 chevron 아이콘은 승인된 Figma export를 그대로 사용해야 한다.
- 기존 Figma 기능성 아이콘을 손으로 다시 그리지 않는다.

브랜드 픽셀 아이콘:

- 새로운 동물, 왕관, 뱃지, 반응 및 브랜드 내비게이션 에셋은 픽셀 SVG로 제작할 수 있다.
- 아래의 그리드, 팔레트, 외곽선 및 상태 규칙을 따라야 한다.

### 11.3 픽셀 제작 규칙

- SVG에는 `shape-rendering="crispEdges"`를 사용해야 한다.
- 32px 내비게이션 아이콘은 2px 물리 셀로 구성한 `16 x 16` 논리 그리드를 권장한다.
- 32px 크기에서 최소 디테일과 음영 공간 간격은 `2px`다.
- 정수 좌표에 정렬된 채움 사각형 또는 직교 채움 path를 사용한다.
- 픽셀 기하에 안티앨리어싱되는 CSS stroke를 사용하지 않는다.
- 표준 동물 픽셀 외곽선: `Main/500 #AD651D`
- 기본 비활성 아이콘: `#A6A6A6`
- 일러스트 팔레트: 아이콘당 4–6색 이하
- 그라디언트와 흐린 효과를 사용하지 않는다. 동물 패밀리의 가장 어두운 모색 `#231406`은 몸과 무늬에만 사용할 수 있으며 표준 외곽선을 대체하지 않는다.
- Fill과 stroke variant는 동일한 캔버스와 외부 실루엣을 공유해야 한다.
- 투명 배경이 필수다.
- 확대 화면뿐 아니라 실제 UI 크기에서 에셋을 검토해야 한다.

무거운 아이콘 패밀리는 약 40px 크기에서 4px 외곽선 블록을 사용할 수 있다.
단, 같은 세트의 모든 형제 아이콘이 동일한 시각적 굵기를 사용해야 한다.

### 11.4 표준 동물 캐릭터 제작 프레임

포퐁 표준 픽셀 동물 캐릭터의 공식 기하 기준은
[Figma 노드 `3504:103765` — `pawpong-pixel-cat (grid-adjusted)`](https://www.figma.com/design/7VXGIjqr1eZBEmsp3OPNie/2026-pawpong?node-id=3504-103765)다.

| 속성 | 필수값 |
|---|---:|
| SVG 캔버스 및 `viewBox` | `155 x 155px` / `0 0 155 155` |
| 물리 픽셀 모듈 | `5 x 5px` |
| 논리 캔버스 그리드 | `31 x 31칸` |
| 전체 논리 캔버스 셀 | `961개` |
| 표준 캐릭터 영역 | `100 x 95px` |
| 표준 캐릭터 그리드 | `20 x 19칸` |
| 캐릭터 시작점 | `x=25px`, `y=30px` |
| 캔버스 여백 | 왼쪽 `25px`, 오른쪽 `30px`, 위 `30px`, 아래 `30px` |

규칙:

- 별도의 대상 Figma 노드 또는 사용자의 명시적 승인이 다른 크기를 정의하지 않는 한, 새로운 표준 포퐁 동물 캐릭터 SVG는 `155 x 155px` 캔버스와 `31 x 31` 논리 그리드를 사용해야 한다.
- 제작 픽셀 한 칸은 `5 x 5px` 모듈 한 칸과 같아야 한다. 좌표, 너비, 높이, 실루엣 단계, 디테일 및 음영 공간은 5px 그리드에 맞춰야 한다.
- 기본 캐릭터 실루엣은 `(25, 30)`에서 시작하는 `100 x 95px` 영역 안에 있어야 한다. 포즈 variant는 이 영역 안의 셀을 투명하게 비울 수 있지만, 별도 승인된 레이아웃 frame 없이 영역 밖으로 나가면 안 된다.
- 비대칭 가로 여백은 의도된 값이다. 왼쪽 5칸, 오른쪽 6칸이며 위아래 여백은 각각 6칸이다.
- SVG 출력에는 `width="155"`, `height="155"`, `viewBox="0 0 155 155"`, `shape-rendering="crispEdges"`를 선언해야 한다.
- 배경은 투명해야 한다. 캔버스 크기를 유지하려는 목적으로 155px 배경 사각형을 추가하지 않는다.
- 소수점 좌표를 새로 작성하면 안 된다. 기존 Figma vector에 약 `0.001px` 수준으로 존재하는 소수점 편차는 변환 노이즈이며 새 에셋에서는 정확한 5px 배수로 정규화해야 한다.
- 이 프레임 규칙은 기하와 배치만 제어한다. 모색, 외곽선, 얼굴 디테일 및 하이라이트 색상은 승인된 동물 패밀리 팔레트와 대상 Figma 에셋을 계속 따라야 한다.
- 기준 프레임에는 현재 136개 vector 레이어가 있지만 이는 구현 세부사항이며 필수 픽셀 또는 레이어 개수가 아니다. 선명한 그리드 기하를 유지할 수 있다면 인접한 같은 색 셀을 병합하는 것을 권장한다.
- `155 x 155px`와 실제 UI 표시 크기에서 검토한다. 확대 검토는 그리드 품질 확인을 위한 보조 수단으로만 사용한다.

### 11.5 동물 공식 원형 잠금

기존 포퐁 픽셀 동물을 레퍼런스에 맞춰 변형하기 전에 필수 문서인
[`PAWPONG_PIXEL_ANIMAL_RULES.md`](./PAWPONG_PIXEL_ANIMAL_RULES.md)를 읽고 따라야 한다.

- 기존 SVG와 사진 레퍼런스가 함께 제공된 요청은 새 형태 탐색이 아니라 원형 잠금 변형을 기본값으로 한다.
- 원형 잠금 모드에서 사진은 허용된 모색, 무늬 및 문서화된 색 관계만 제공한다. 새로운 실루엣, 포즈, 표정, 신체 비율, 다리 위치 또는 꼬리 위치를 허가하지 않는다.
- 현재 공식 고양이 기하는 `assets/pixel-animals/canonical/pawpong-cat-base-100x95.svg`다.
- 공식 고양이는 `100 x 95px`, `20 x 19칸` 형태에 순서가 고정된 136개 원본 path를 갖는다. 새로운 모색 variant는 원본과 결과에 동일한 결정론적 5px 그리드 정규화를 적용한 뒤에도 이 순서와 기하를 유지해야 한다.
- 무늬 overlay는 승인된 몸 픽셀 마스크 안에만 추가할 수 있다. 외곽선, 투명 셀, 고정된 얼굴 디테일 또는 보호된 입 주변 영역을 덮으면 안 된다.
- 새 실루엣이나 포즈를 만들려면 명시적인 새 형태 요청과 사용자 승인이 필요하다. 사진에 다른 포즈가 보인다는 사실만으로는 충분하지 않다.
- 원형 잠금 결과가 기하, 마스크, 캔버스, 그리드, 팔레트 또는 투명도 검증에 실패하면 완성본으로 전달하면 안 된다.
- 전용 Skill이 설치된 경우, 오래된 값을 내부에 복사해 사용하지 말고 매 실행마다 현재 하네스와 픽셀 동물 규칙을 읽어야 한다.

### 11.6 동물 모색 무늬 대비

레퍼런스를 적용한 픽셀 동물 패밀리의 모색 대비는 모든 무늬에 가장 어두운
일러스트 색상을 기본 적용하지 말고 실제 표현형을 따라야 한다.

- 흰색 위 검은 점박이와 턱시도 무늬처럼 고대비 모색은 패밀리의 가장 어두운 털색을 사용할 수 있다. 승인된 고양이 패밀리에서는 `#231406`이다.
- 치즈태비처럼 유사색 또는 저대비 모색은 가장 어두운 털색을 고려하기 전에 몸과 같은 hue 패밀리의 더 낮은 명도 색상을 사용해야 한다.
- `#F6C65D` 치즈 몸에는 승인된 오렌지 음영 `#C76516`을 무늬로 사용한다.
- 따뜻한 유사색 모색의 무늬를 더 선명하게 보이게 하려는 이유만으로 `#231406`을 사용하지 않는다. 실제 털색 관계를 보존하고 에셋의 실제 크기에서 가독성을 검토한다.
- 이 규칙은 털 채움만 제어한다. 패밀리에서 승인된 외곽선, 눈, 코, 입, 귀 또는 수염 역할은 변경하지 않는다.

## 12. 상호작용 상태

브랜드 인터랙션은 `main`, `sub`, `point` 중 컴포넌트에 지정된 한 계열 안에서
상태 단계를 전환한다. 서로 다른 계열을 상태 변화처럼 임의 교차 사용하면 안 된다.

| 상태 | Main 예시 | Sub 예시 | Point 예시 |
|---|---:|---:|---:|
| Default | `#AD651D` | `#F6C65D` | `#FFFE72` |
| Hover | `#BD8348` | `#F8D17D` | `#FFFEAA` |
| Press | `#8A5117` | `#CDA44B` | `#DBDA5B` |
| Selected | `#683D11` | `#A48239` | `#B6B644` |
| Inverse | `#FFFFFF` | `#FFFFFF` | `#FFFFFF` |
| Disabled | `Colors/text/disabled #B8B8B8` | `Colors/bg/disabled #E4E4E4` | 브랜드 계열 대신 공통 disabled 토큰 사용 |

규칙:

- 상태는 색상에만 의존하면 안 된다. 테두리, 채움, 라벨 또는 형태 변화를 함께 사용한다.
- Figma 상태가 불완전하더라도 코드에서 focus 표시를 유지해야 한다.
- `Press`는 누르는 동안의 순간 상태, `Selected`는 선택이 유지되는 상태다. `Active`라는 이름으로 두 상태를 합치지 않는다.
- Disabled 토큰은 등록되어 있다. focus와 loading 표현은 대상 Figma variant를 확인하고, 근거 없이 영구 토큰을 만들지 않는다.

## 13. 카피 및 보이스

포퐁 카피는 따뜻하고, 직접적이며, 존중하는 태도로 반려동물을 중심에 두고
빠르게 읽을 수 있어야 한다.

권장 동사:

- 찾기
- 둘러보기
- 만나기
- 함께하기
- 공유하기
- 곁에 있기

피해야 할 표현:

- 과도한 아기 말투
- 밈에 지나치게 의존하는 언어
- 반복되는 문장부호 또는 장식 기호
- 두려움을 이용한 전환 카피
- 동물을 소비 가능한 상품으로 취급하는 표현

## 14. 접근성 기준선

- 핵심 본문은 WCAG AA 대비를 충족하는 것을 권장한다.
- 아이콘과 큰 그래픽 컨트롤은 인접 표면과 최소 3:1 대비를 갖는 것을 권장한다.
- 18px 미만 텍스트는 장식용 일러스트 색상만을 전경색으로 사용하면 안 된다.
- 아이콘 전용 컨트롤에는 접근 가능한 이름을 제공해야 한다.
- 눈에 보이는 focus를 유지해야 한다.
- 보이는 glyph가 더 작더라도 터치 대상은 최소 `44 x 44px`를 권장한다.
- 콘텐츠 역할을 하는 동물 사진에는 유용한 대체 텍스트를 제공해야 한다.

## 15. 필수 작업 절차

UI, 카피 또는 에셋을 변경하기 전:

1. 이 문서를 읽는다.
2. Figma `get_design_context`로 대상 노드를 읽는다.
3. 현재 컴포넌트와 승인된 에셋을 확인한다.
4. 정확한 시맨틱 토큰과 컴포넌트 variant를 확인한다.
5. 에셋이 기능성인지 브랜드 픽셀인지 결정한다.
6. 픽셀 동물 작업이라면 `PAWPONG_PIXEL_ANIMAL_RULES.md`를 읽고 원형 잠금 변형인지 명시적으로 승인된 새 형태 탐색인지 분류한다.

구현 중:

1. 새 컴포넌트를 만들기 전에 기존 컴포넌트를 재사용한다.
2. 등록된 시맨틱 토큰을 사용한다.
3. 공식 `main/sub/point` Primitive와 시맨틱 alias를 사용하며, 화면 전용 원시값은 문서에 지정된 역할에만 사용한다.
4. Figma 치수, 간격, radius 및 상태 동작을 보존한다.
5. 새로운 브랜드 색상, 폰트 스타일, 그림자 또는 radius를 알리지 않고 추가하지 않는다.
6. 원형 잠금 모드에서는 문서에 허용된 속성만 변경하고 공식 원형의 path 순서와 기하를 보존한다.

구현 후:

1. 프로젝트 build를 실행한다.
2. 대상 범위에 맞게 데스크톱, 태블릿 및 모바일 동작을 확인한다.
3. 실제 크기에서 아이콘 가독성을 확인한다.
4. 해당하는 hover, press, selected, focus, disabled, loading 및 empty 상태를 확인한다.
5. 결과를 Figma screenshot과 비교한다.
6. 원형 잠금 픽셀 동물은 전달하기 전에 기하, 몸 마스크, 그리드, 캔버스, 팔레트 및 투명도 검증을 실행한다.

## 16. 승인 체크리스트

적용 가능한 다음 항목을 모두 통과하기 전에는 브랜드 작업이 완료된 것으로 간주하지 않는다.

- [ ] 대상 Figma context를 읽었다.
- [ ] 기존 컴포넌트와 에셋을 검색했다.
- [ ] 승인된 토큰 또는 문서화된 원시 브랜드 값만 사용했다.
- [ ] 타이포그래피 스타일과 행간이 시스템과 일치한다.
- [ ] 간격과 radius가 승인된 scale에서 나왔다.
- [ ] 기능성 아이콘은 승인된 정확한 export를 사용한다.
- [ ] 픽셀 에셋은 선명하고 정렬된 기하를 사용한다.
- [ ] 픽셀 동물 작업을 원형 잠금 또는 명시적 새 형태로 분류했다.
- [ ] 원형 잠금 동물의 기하와 보호 영역이 검증을 통과했다.
- [ ] 형제 아이콘이 동일한 시각적 굵기를 사용한다.
- [ ] 상호작용 상태를 색상 없이도 구분할 수 있다.
- [ ] 카피가 포퐁 보이스를 따른다.
- [ ] 접근성 라벨과 focus 동작이 존재한다.
- [ ] build 및 시각 검증을 통과했다.

## 17. 확인된 시스템 부채

- 현재 색상 namespace와 레거시 namespace가 함께 존재한다.
- 시맨틱 컬렉션 이름이 Figma에서 `Sementic`으로 오기되어 있다.
- 기존 `primary color/secondary color`와 현재 `main color/sub color/point color` namespace가 함께 남아 있을 수 있다.
- 화면 전용 일러스트 색상이 모두 변수로 등록돼 있지는 않다.
- gap, padding 및 size alias가 spacing primitive를 중복한다.
- 버튼 variant의 상태명이 `Default/default`, `disabled/disable` 등으로 혼재한다.
- 버튼 크기명이 숫자, `lg/md`, `large/medium`으로 혼재한다.
- 카페24 프로업의 변수상 Bold 선언과 실제 로컬 Text Style의 Regular/400 해석 사이에 차이가 있다.
- 기존 홈 동물 컴포넌트의 154px 캔버스와 새 표준 동물 에셋의 155px 캔버스가 함께 존재한다.
- focus와 loading variant는 검토한 컴포넌트 세트에서 불완전하다.
- 배너와 명예 영역이 여전히 원시 색상 값에 의존한다.

기능 작업 중 이 부채를 알리지 않고 해결하지 않는다. 여러 컴포넌트에 영향을
주는 변경이라면 기록하고 별도의 디자인 시스템 마이그레이션을 요청한다.

## 18. 하네스 변경 관리

- 이 문서를 변경하려면 Figma 근거 또는 사용자의 명시적 승인이 필요하다.
- 규범적 변경이 있을 때 버전과 검토일을 갱신한다.
- 추가 설명은 patch 버전을 올릴 수 있다.
- 토큰 또는 컴포넌트 규칙 변경은 minor 버전을 올린다.
- 브랜드 방향 변경은 major 버전을 올린다.
- 테스트 에셋은 명시적으로 승인되기 전까지 공식 에셋이 아니다.
