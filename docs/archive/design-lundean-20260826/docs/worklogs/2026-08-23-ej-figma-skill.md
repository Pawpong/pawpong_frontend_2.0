# ej-figma 스킬 신설 — 코드 화면을 Figma 컴포넌트로 반영

- 작성자: 최은진
- 날짜: 2026-08-23
- 범위: 커뮤니티 홈 / 상세 모달·페이지 화면을 Figma 재사용 컴포넌트로 반영하는
  신규 스킬(`ej-figma`) 설계

## 요청 배경

이 저장소에서 만든 커뮤니티 화면(홈, 상세 모달/페이지)을 반응형별로 Figma에
컴포넌트로 반영하는 작업을, 매번 새로 설명하지 않아도 되게 스킬로 고정해달라는
요청이었다. 실제 작업을 시작하기 전에 "코드 화면을 Figma에 컴포넌트로 붙여넣는
게 애초에 가능한가"부터 확인했고, Figma MCP에 정확히 이 용도의 도구
(`generate_figma_design` — 로컬 dev 서버를 픽셀 단위로 캡처, `use_figma` +
`search_design_system` — 실제 디자인 시스템 컴포넌트로 재조립)가 이미 있는 것을
확인한 뒤 스킬을 설계했다.

## 진행한 작업

1. **가능 여부 확인** — `generate_figma_design`/`create_new_file` 툴 스키마를
   직접 로드해서, 로컬 dev 서버(localhost) 캡처 기능과 "`generate_figma_design` +
   `use_figma`/`search_design_system` 병행 → 재조립 후 캡처본 삭제"라는 공식
   워크플로우가 문서화돼 있음을 확인했다.
2. **대상 확정** — Figma 파일 `7VXGIjqr1eZBEmsp3OPNie`("2026-pawpong")의
   "6. 커뮤니티" 페이지(`3349:2149758`)에 배치하기로 확정.
3. **기존 구조 사전 조사** — 스킬을 쓰기 전에 해당 페이지를 `get_metadata`로
   전수 조사해서, **이미 부분적으로 시작된 작업**을 발견했다:
   - `(수정)커뮤니티 홈` 섹션(`3557:417738`)에 `Community Feed Card` 컴포넌트
     (`type=img`/`type=txt` 베리언트)가 이미 있고, mo(375)·pc(1440)에는 인스턴스로
     배치돼 있지만 **tab(768)은 비어 있음**.
   - `게시글 상세 모달 (MCP 업데이트 · 인스타그램 웹 스타일)` 컴포넌트도 이미
     있지만 **PC 크기(1120×680)로만** 존재 — tab(스택형)과 mo(모달이 아닌 실제
     페이지) 버전이 없음.
   - `comment-input`(default/focus/답글달기), `scroll interaction` 등 부속
     컴포넌트도 이미 있음.
   - 이 사실들을 스킬 문서에 실제 노드 ID와 함께 그대로 박아 넣어서, 다음에
     스킬을 쓸 때 이 페이지를 처음부터 다시 파악할 필요 없게 했다(단, 스킬 안에
     "실행할 때마다 최신 상태를 다시 확인하라"는 문구도 넣어 이 스냅샷이 시간이
     지나면 낡을 수 있다는 점을 명시했다).
4. **비타협 규칙 4개 명문화** — 사용자가 정한 조건을 스킬의 규칙으로 고정:
   ① 화면 하나 = pc/tab/mo 3종 세트가 기본 단위, ② 요청받은 화면만 작업(다른
   화면은 안 건드림), ③ 결과물은 정적 프레임이 아니라 재사용 가능한 Figma
   Component(Set), ④ 만들기 전에 파일 전체를 훑어 이미 있는 컴포넌트는
   재사용하고 없는 것만 새로 만듦.
5. **소스 오브 트루스 명시** — 두 화면의 실제 코드 위치·라우트 접근 방법과,
   반응형 정책 배경 문서(`docs/worklogs/2026-08-23-community-detail-responsive.md`)를
   스킬에서 바로 참조하도록 연결했다.
6. **8단계 워크플로우 작성** — 범위 확정 → dev 서버 확인 → 기존 컴포넌트
   서베이 → 브레이크포인트별 캡처+재조립 → 컴포넌트화 → 배치(기존 네이밍 규칙
   준수) → 검증(로컬 앱 스크린샷과 대조) → 보고.

## 확인/검증

- `generate_figma_design`/`create_new_file` 툴 스키마를 실제로 로드해서 존재와
  설명을 확인했다(추측 아님).
- 대상 페이지(`3349:2149758`)를 `get_metadata`로 실제로 읽어서 기존
  컴포넌트/섹션 구조(위 3번 항목)를 직접 확인했다.
- **미확인**: 이번 세션에서는 스킬 정의만 완료했고, `/ej-figma`를 실제로
  실행해서 화면을 만드는 작업은 하지 않았다. Design System
  페이지(`139:70`)의 실제 컴포넌트 목록도 아직 조사하지 않았다 — 스킬 실행 시
  3단계("기존 컴포넌트 서베이")에서 확인하도록 설계만 해뒀다.

## 남은 작업 / 참고사항

- 다음에 `/ej-figma`를 실제로 실행할 때는 먼저 범위(커뮤니티 홈 / 상세
  모달·페이지 / 둘 다)를 정해야 한다.
- 두 화면 모두 **tab(768) 브레이크포인트가 가장 먼저 채워야 할 빈 자리**다.
- mo 상세는 "모달이 아니라 실제 페이지 이동"이라는 점이 지금 Figma 파일에는
  아직 반영돼 있지 않다 — 실행 시 이 구분을 목업에서도 시각적으로 드러나게
  만들어야 한다(예: 모달 X 버튼이 없고 뒤로가기 화살표만 있는 풀페이지 구성).
