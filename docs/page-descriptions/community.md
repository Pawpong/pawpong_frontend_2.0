# 커뮤니티

- 라우트: `/community` (홈), `/community/[postId]` (상세 페이지·mo), `/community/write`(작성), `/community/drafts`(임시저장), `/community/[postId]/edit`(수정)
- 코드 위치: `src/app/(main)/community/`
- 최종 갱신: 2026-08-25

## 개요

반려동물 사진·글을 올리고 좋아요·댓글·북마크로 반응하는 인스타그램 홈 방식의
단일 컬럼 피드다. 피드 카드의 댓글 아이콘을 누르면 피드 뒤에 남긴 채 상세를
모달로 띄우거나(pc/tab), 실제 페이지로 이동(mo)한다 — 인스타그램 웹과 동일한
"피드에선 모달, 퍼머링크는 풀페이지" 동작이다.

## 주요 기능

- 최신순 글 무한스크롤 피드(이미지 캐러셀 카드 / 텍스트 전용 카드)
- 검색(버튼 클릭 시 pill이 입력창으로 확장, mo는 항상 전체 폭)
- 좋아요·북마크 토글, 댓글 수 표시
- 댓글 아이콘 클릭 → 게시글 상세 + 댓글 스레드(모달 또는 페이지, 아래 참고)
- 댓글 작성/답글(1단계 스레드)/수정/삭제(본인 댓글만)
- 게시글 작성(`/community/write`)/임시저장(`/community/drafts`)/수정/삭제(본인 글만)
- 우하단 고정 "글작성" FAB

## 화면 구성 — 커뮤니티 홈 (`/community`)

| 영역 | 설명 | 코드 위치 |
|---|---|---|
| 검색 행 | 공통 헤더 바로 다음, 우측 정렬 검색 트리거(mo는 풀폭 pill) | `_ui/CommunityContent.tsx` |
| 피드 | 단일 컬럼 카드 목록. tab+는 415px로 좁혀 가운데 정렬, mo는 좌우 여백 없이 화면 꽉 참. 카드 간격은 브레이크포인트 무관 36px 고정 | `_ui/CommunityFeedCard.tsx` |
| 글작성 FAB | 우하단 고정, `/community/write`로 이동 | `_ui/CommunityContent.tsx` |

카드 내부(이미지형/텍스트형 공통): 헤더(아바타+닉네임+작성시각+더보기) →
미디어(1:1 캐러셀 또는 큰 텍스트) → 액션(좋아요/댓글/북마크) → 캡션(이미지형만,
닉네임+본문 한 줄).

## 화면 구성 — 게시글 상세 (댓글 아이콘 클릭 시)

pc/tab은 모달, mo는 페이지지만 셋 다 같은 `PostDetailPanel`을 씀 — pc만
`side-by-side`(이미지 60%+패널 40%), tab/mo는 `stacked`(세로 나열) 레이아웃.

| 영역 | pc(side-by-side) | tab/mo(stacked) |
|---|---|---|
| 헤더 | 아바타+닉네임+팔로우+닫기(X) | 동일 |
| 이미지 캐러셀 | 좌측 60%, 세로 꽉 참 | 헤더 바로 다음, 정사각 전체 폭 |
| 액션바(좋아요/댓글/북마크) | 우측 패널 맨 아래 고정, 더보기(⋯)는 여기 없음 | 이미지 바로 다음(캡션보다 위), 더보기(⋯)가 이 줄 오른쪽 끝 |
| 캡션 | 액션바 위, 더보기(⋯) 포함 | 액션바 다음, 더보기 없음 |
| 댓글 영역 | 캡션 아래 남는 공간 전부 스크롤 | 캡션 다음, 이미지부터 댓글까지 한 스크롤 영역 |

## 인터랙션 · 상태

- **스크롤/고정 요소**:
  - "글작성" FAB — `fixed right-6 bottom-6 z-40`, 스크롤과 무관하게 항상 우하단
    고정(피드 홈에서만).
  - 게시글 상세 모달 — `DialogPrimitive.Content`가 `fixed top-1/2 left-1/2
    -translate-x-1/2 -translate-y-1/2`로 항상 뷰포트 정중앙 고정, 배경 오버레이도
    `fixed inset-0 z-[60]`.
  - 그 외 피드 자체엔 스크롤 기반 sticky 전환 없음(무한스크롤만 있음).
- **의미 있는 로컬 상태**:
  - `searchOpen`/`query`(`CommunityContent`) — 검색 트리거 ↔ 입력 pill 전환,
    비어 있는 채로 포커스를 잃으면 자동으로 트리거로 복귀.
  - 게시글 상세 모달 표시 여부는 React state가 아니라 **라우팅 상태**다 — Next.js
    인터셉트 라우트(`@modal/(.)[postId]`) 진입 여부로 결정되고, `isTabUp`
    (`useBreakpoint('tab')`)에 따라 모달로 보여줄지 `/community/[postId]`로 하드
    네비게이션할지 갈린다.
  - `confirmDeletePost`/`confirmDelete`(댓글) — 삭제 확인 모달 노출.
  - `replyTarget`(`CommentSection`) — 답글 대상 댓글이 잡히면 입력창 placeholder가
    바뀌고 취소 배너가 뜬다.
  - 좋아요/북마크는 각각 `isLikePending`/`isBookmarkPending`으로 낙관적 토글 중
    버튼을 잠깐 비활성화(`disabled:opacity-50`).

## 모션 디테일

- 게시글 상세 모달 열림/닫힘: `data-[state=closed]:opacity-0
  data-[state=open]:opacity-100`로 opacity만 토글, **트랜지션 지속시간(duration)
  지정 없음** → 사실상 즉시 전환(부드러운 페이드인이 아님).
- 이미지 캐러셀 좌우 화살표(hover): `transition`/`transition-all` 클래스는 있으나
  지속시간 값 미지정(브라우저 기본값 사용) — 정확한 속도 스펙 없음.

## 사용자 플로우

- 피드 카드 댓글 아이콘 클릭:
  - **pc(1440~)**: 뒷배경 딤(`bg-black/50`) + **1120×680 고정** side-by-side 모달
  - **tab(768~1439)**: 뒷배경 딤 + **420×1100(뷰포트 작으면 최대 85vh로 축소)**
    stacked 모달
  - **mo(~767)**: 모달이 아니라 `/community/[postId]`로 하드 네비게이션(페이지 이동),
    같은 stacked 레이아웃을 페이지로 그대로 사용
- 모달 닫기(X·바깥 클릭·ESC) → `router.back()`으로 원래 위치 복귀
- 게시글 작성 → `/community/write`, 임시저장 있으면 마이홈 게시글 탭에서 이어쓰기
  진입점 노출
- 본인 글/댓글만 더보기(⋯) 메뉴로 수정/삭제 가능

## 권한 · 로그인 분기

| 상황 | 노출/동작 결과 |
|---|---|
| 본인이 쓴 글/댓글 | 더보기(⋯) 메뉴로 수정·삭제 가능 |
| 남이 쓴 글/댓글 | 더보기 메뉴 노출 안 됨 |
| 비로그인 사용자 | 댓글 입력창은 로그인 상태(또는 `mock-*` 임시 미리보기 글)일 때만 노출됨. 좋아요·북마크 버튼은 로그인 여부와 무관하게 항상 노출 — 비로그인 클릭 시 실제 동작은 별도 확인 필요 |

## 반응형 정책

- 피드: tab부터 415px 좁은 폭(이미지 강조), mo만 풀폭+각 카드도 화면 끝까지.
  카드 모서리는 mo 포함 전 구간 16px 라운드 통일.
- 게시글 상세: pc는 side-by-side, tab/mo는 stacked — 레이아웃 종류 자체가
  브레이크포인트로 갈린다(위 표 참고). mo는 모달이 아니라 페이지라는 점도
  브레이크포인트 정책의 일부.
- 검색 트리거: mo는 항상 풀폭(`w-full justify-between`), tab+는 컨텐츠 폭에
  맞는 컴팩트 버튼(`w-auto`), 포커스(입력 모드) 시엔 mo 풀폭/tab+ 최대 300px.

## 데이터 · 상태

- 피드: `communityQueries.posts('latest')` 무한스크롤. 개발 환경에서 API가
  실패/빈 목록이면(`NODE_ENV !== 'production'`) `MOCK_COMMUNITY_FEED`로 폴백 —
  운영 빌드에서는 노출 안 됨.
- 게시글 상세: `usePostDetail(postId)` 훅에 조회·좋아요/북마크 토글·삭제 로직이
  모여 있고, 모달(`PostDetailModalBody`)과 페이지(`PostDetailContent`)가 이 훅과
  `PostDetailPanel`을 공유한다.
- 댓글: `CommentSection` — `communityQueries.comments(postId)` 무한스크롤,
  1단계 스레드(최상위+답글)로 재구성. `mock-*` 글(postId가 `mock-`으로 시작)은
  로그인 여부와 무관하게 `MOCK_ME`로 댓글 작성 UI를 미리 볼 수 있음(실제 글은
  로그인 필요).
- 삭제된 부모 댓글 아래 답글이 남아있으면 "삭제된 댓글입니다." 자리를 만들고
  답글은 그대로 보여준다(답글달기는 막음).

## 엣지 케이스

| 상황 | 현재 처리 상태 |
|---|---|
| 닉네임이 매우 길 때 | 처리됨 — 한 줄 말줄임(`truncate`) |
| 텍스트 게시글 본문이 매우 길 때 | 처리됨 — 카드에서 6줄로 잘림(`line-clamp-6`), "더보기" 없음 |
| 프로필 이미지가 없을 때 | 처리됨 — 발바닥 아이콘 플레이스홀더로 대체(`CommunityAvatar`) |
| 프로필 이미지 URL은 있지만 로드 실패할 때 | 미구현 — `onError` 폴백 없음, 깨진 이미지로 보일 위험 |
| 피드 카드에서 좋아요/북마크 연타할 때 | 미구현 — 버튼이 막히지 않음(pending 상태 미반영). 상세 화면(모달/페이지)은 `disabled`로 막혀 있어 카드와 동작이 다름 |

## 접근성

- 확인됨: 아이콘 전용 버튼(더보기·좋아요·댓글 보기·북마크·닫기) 전부
  `aria-label`로 스크린리더 안내 텍스트 있음. 게시글 상세 모달엔 스크린리더
  전용 타이틀("게시글 상세")이 있어 무엇이 열렸는지 안내됨. 검색·댓글 입력창은
  포커스 시 테두리 색이 바뀌어 포커스 위치가 시각적으로 보임.
- 확인 안 됨: 이미지 캐러셀 좌우 이동, 모달 안 포커스 이동(트랩)이 키보드만으로
  되는지는 코드에서 별도 구현이 안 보임 — 실제 테스트 필요.

## 완료 기준 체크리스트

- ☐ pc/tab/mo 3개 폭에서 레이아웃이 깨지지 않는다 (필수)
- ☐ 댓글 아이콘 클릭 시 pc·tab은 모달/mo는 페이지로 정확히 분기된다 (필수)
- ☐ 좋아요·북마크 연타해도 화면이 깨지거나 중복 요청이 안 나간다 (확인 필요 — 현재 피드 카드는 미구현 가능성)
- ☐ 이미지 로드 실패 시 빈 화면 대신 대체 UI가 보인다 (확인 필요 — 현재 미구현)
- ☐ 키보드만으로 피드 탐색·댓글 열기·모달 닫기가 가능하다 (확인 필요)

## 참고

- Figma: "6. 커뮤니티" 페이지, `(수정)커뮤니티 홈` 섹션(node `3557:417738`, 홈
  pc/tab/mo raw capture) — 이 파일의 Pretendard 폰트 로드 문제로 아직 컴포넌트
  인스턴스가 아닌 캡처본 상태(비타협 규칙 3 미충족, `/ej-figma` 참고). 게시글 상세는
  "피드 상세보기" 섹션(node `3349:2149847` → `feed-detail` 컴포넌트, device=pc/
  device=tab-mo 베리언트)을 소스로 삼아 코드에 반영 완료.
- `PostDetailModal`이 인터셉트 라우트(Next.js Intercepting Routes,
  `@modal/(.)[postId]`)로 구현돼 있어, Turbopack dev 캐시가 꼬이면
  `Invalid interception route` 에러로 모달 대신 풀페이지로 빠지는 알려진 버그가
  있다 — 증상 발견 시 `.next` 삭제 후 dev 서버 재시작.
- 댓글 입력창 높이(40px), 액션바 패딩(`px-3 py-2`), 캡션 간격(10px) 등은 Figma
  `feed-detail` 컴포넌트를 `get_design_context`로 재확인해서 맞춘 값 — 임의로
  둥글게 잡지 않았음.
