## 이번 점검에서 확인한 결함

- 웹 배포 후 이전 JS/CSS 파일을 읽지 못한 화면에서 React 재시도만 실행해 같은 오류가 반복될 수 있었음. 해당 오류는 문서 전체를 새로 읽고, 일반 오류는 기존 React 재시도를 유지하도록 수정함.
- access 쿠키가 먼저 만료되면 남아 있는 refresh 세션을 복구하기 전에 로그인 화면으로 이동할 수 있었음. 일시적인 네트워크 장애와 세션 무효 응답도 구분이 필요했음.
- Android 파일 선택기에서 카메라 권한을 실제 요청하는 경로가 없었음. 비동기 권한 응답 뒤에는 파일 선택기를 여는 사용자 탭도 유지해야 함.
- 웹 공유 기능과 새 창 이동을 앱에서 처리하는 경로, 렌더러 종료 뒤 현재 화면으로 돌아오는 동작이 부족했음.
- 채팅 전송 성공을 확인하기 전에 입력이 비워지고, 재연결·재전송에 대한 서버 확인과 중복 방지 계약이 부족했음.
- 채팅 사진 첨부가 공용 HEIC 변환 경로를 사용하지 않아 수신 환경에서 표시가 안 될 수 있었음. 기존 사진 변환을 재사용하도록 연결함.
- 정지 계정의 기존 JWT·refresh·연결된 채팅을 거절하는 상태 검사가 부족했음.
- 업데이트 정책의 스토어 주소가 다른 앱을 가리킬 수 있고, 잘못된 기존 주소 때문에 비활성화도 막힐 수 있었음.

## 운영 시 남는 제한

- 채팅 초안 보존은 같은 문서 안의 응답 유실과 재접속을 대상으로 함. 앱 프로세스 종료나 문서 전체 새로고침을 가로지르는 초안 영구 저장은 구현하지 않음.
- 채팅의 고유 식별자는 중복 저장과 동일 요청 재시도를 처리함. 메시지 저장 직후 서버가 종료되는 경우의 방 메타데이터·브로커·알림까지 원자적으로 완료하는 outbox 계약은 아니며 종단 간 exactly-once를 보장하지 않음.
- 실제 로컬 웹의 공유 주소는 HTTP이므로 RN의 HTTPS 전용 공유 정책이 거절하는 것이 정상임. 로컬 화면의 오류/URL 복사 경로와 HTTPS 진단 페이지의 OS 공유 성공을 분리해 검증함.
- 앱 오류 경계와 WebView 복구는 있지만 운영 네이티브 크래시를 중앙 수집·알림하는 새 시스템은 이번에 추가하지 않음.
- 정지·탈퇴 계정의 access JWT는 매 요청의 상태 확인으로 거절함. 계정을 다시 활성화하면 아직 만료되지 않은 과거 access JWT가 유효할 수 있으며 tokenVersion을 이용한 영구 취소 모델은 도입하지 않음. 제거한 refresh 세션은 재활성화해도 복구되지 않음.
