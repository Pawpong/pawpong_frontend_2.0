# AI 필터 조회 타임아웃 복구

2026-10-02 KST. 사용자 제보는 `timeout of 30000ms exceeded`가 보였으나 사진은 생성됐다는 내용이다. 생성 요청을 임의로 다시 보내지 않고 기존 작업을 복구한다.

## 운영 관찰과 판단

- 현재 운영 서버의 백엔드·AI 에이전트 Docker 로그를 읽기 전용으로 확인했다. 운영 DB, 사용자 사진, 계정 설정은 변경하지 않았다.
- 현재 운영 컨테이너는 02:14 KST 시작 후 재시작 횟수 0이었다. 백엔드 GitHub 운영 배포는 02:11 성공했고, 웹의 최신 Production 배포 `67ee83c`도 02:09 성공했다. 확인한 09시대 요청은 배포 시각과 겹치지 않는다.
- 작업 A는 09:06:51 생성 접수 HTTP 200 / 4,956ms, 09:06:54 상태 조회 HTTP 200 / 10ms였다. 에이전트는 09:07:32 성공 결과를 발행했다. 뒤의 상태 조회는 없었고 09:09:10 결과 다운로드는 HTTP 200이었다.
- 작업 B는 09:08:45 생성 접수 HTTP 200 / 2,495ms였다. 09:09:08까지의 상태 조회는 8~10ms / HTTP 200이었으나 완료 직전 폴링이 끊겼고 에이전트는 09:09:20 성공 결과를 발행했다.
- 프론트 기본 Axios 요청 제한은 30초다. 기존 훅은 상태 GET이 한 번 타임아웃돼도 전체 흐름을 failed로 바꾸고 원시 오류 메시지를 그대로 노출했다. 서버의 Kafka 작업은 브라우저 연결과 독립적으로 계속 실행되므로 화면 오류와 결과 생성이 함께 나타날 수 있었다.
- 이는 이미지 생성에 35~42초가 걸려 동기 POST의 30초 제한을 넘겼다는 뜻이 아니다. 실제 접수 POST는 2.5~5초에 끝났고, 상태 조회도 완료된 요청 기준 빠르게 응답했다.
- 제보 사진의 09:04 화면과 위 09:06 이후 작업을 동일 요청이라고 확정하지 않았다. 해당 계정의 클라이언트 네트워크 기록은 없으며, Nginx access.log는 SSH 사용자 권한으로 읽을 수 없었다. 전달받은 이전 서버 주소의 SSH는 연결 시간 초과였다. LTE, WebView, 프록시 중 어디서 요청이 끊겼는지는 이 증거만으로 확정하지 않는다.

## 수정한 동작

- 상태 GET은 개별 10초 제한과 전체 4분 조회 기한 안에서 네트워크 오류·408·429·5xx를 재시도한다. 이미지 다운로드도 제한 시간 안에서 재시도한다. 요청 제한은 남은 전체 기한보다 길게 설정하지 않는다.
- 재연결 중임을 안내하고 전체 생성 실패로 처리하지 않는다. 확인 기한이 끝나면 pending 상태로 보관함 안내와 기존 jobId의 결과 다시 확인을 제공한다. 다운로드만 실패했을 때는 사진이 이미 완성됐음을 안내한다.
- 생성 POST는 자동 재전송하지 않는다. 접수 응답이 유실돼 jobId를 모르는 경우에도 접수 여부가 불확실하다고 안내하고 보관함으로 연결한다.
- 빠른 연속 클릭은 같은 진행 Promise를 공유한다. reset/unmount는 요청과 재시도 대기를 중단하고 이전 응답이 새 작업을 덮어쓰지 못하게 한다.
- 실제 서버의 failed 결과와 4xx 검증 오류는 재시도 대상과 구분한다. 동물 사진 검증 안내를 유지하고 인증·권한·삭제 오류는 사용자 문구로 설명한다.
- 보관함은 pending/queued/processing 작업이 있을 때만 5초마다 갱신한다. 로그인하지 않은 사용자의 조회는 기존처럼 비활성화한다.

## 검증

- `node --test tests/*.test.cjs tests/*.test.mjs`: 177개 통과. 새 회귀 테스트 19개는 `tests/ai-image-recovery.test.cjs`에 둔다.
- 실제 설치된 Axios·API interceptor·HTTP 서버로 첫 상태 응답 timeout을 재현했다. 두 번째 상태 GET과 PNG 다운로드가 성공하고 생성 POST는 정확히 한 번이었다. 이 테스트의 개별 HTTP 시간 제한만 짧게 줄였으며 운영 설정은 별도 API 계약 테스트로 확인한다.
- 모의 시간으로 장시간 연결 끊김, 조회 기한 종료와 같은 작업 resume, 접수 응답 유실, 중복 클릭, 다운로드 재시도, 인증/검증/실제 생성 실패, reset/unmount 이후 늦은 응답을 검증했다.
- 실제 React 컴포넌트 SSR로 pending의 결과 다시 확인·보관함 링크 및 재연결 안내를 확인했다. pending에 다시 생성 버튼과 원시 timeout 문구를 표시하지 않는다.
- 변경 TypeScript/TSX ESLint, TypeScript 검사, Next.js 프로덕션 빌드 통과. CJS 테스트는 저장소의 기존 ESLint 제외 설정을 유지하며 Node 테스트로 실행한다.
- 실제 사용자의 iPhone에서 재검증하거나 운영 생성 횟수를 사용하는 테스트는 수행하지 않았다. 배포 성공과 운영 화면 제공 여부는 dev/main 반영 후 GitHub 배포 상태와 공개 HTTP 응답으로 별도 확인한다.

비밀번호, 토큰, 사용자 사진 URL과 원본 파일키는 이 문서나 코드에 저장하지 않는다.
