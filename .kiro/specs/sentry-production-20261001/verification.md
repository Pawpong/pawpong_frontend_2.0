# 프로덕션 Sentry 알림 이동 오류 검증

2026-10-01 KST. 사용자 요청에 따라 실제 오류를 조사하고 dev에서 수정한 뒤 main으로 승격한다.

## 관찰한 오류와 판단

- `pawpong-web-production`, environment `production`의 최근 14일 이벤트를 Sentry API와 인증된 Orca 브라우저에서 대조했다. 미해결 이슈는 Network Error 4건과 과거 이메일 중복 가입 1건이다. 별도의 중계 검증 이벤트는 resolved 상태이며 제품 오류로 분류하지 않았다.
- [Network Error 이슈](https://pawpong-mq.sentry.io/issues/7743660645/)의 최신 이벤트는 10월 1일 22:47:47 KST, iPhone / iOS 18.7 / WKWebView, 웹 release `1a00fba`다. AOS 네이티브 크래시를 나타내는 기록이 아니다.
- 알림 클릭 뒤 `/applications/:id?_rsc=...` GET이 404를 반환하고, 직후 알림 읽음 PATCH의 status가 0으로 기록됐다. 운영 옛 주소의 실제 HTTP 404도 재현했다. 현재 화면은 `/activity/applications/:id`이며 클라이언트에는 경로 변환 없이 읽음 요청과 router.push를 동시에 실행하는 코드가 있었다.
- 문서 이동이 읽음 요청을 중단한 경합으로 판단해 순서를 보완했다. status 0만으로 모든 네트워크 오류의 원인을 확정하지 않는다. 같은 그룹의 나머지 3건은 9월 20일의 업로드·홈 조회 실패이며, 최신 알림 오류와 동일 원인이라고 주장하지 않는다.
- [중복 가입 이슈](https://pawpong-mq.sentry.io/issues/7760697203/)는 9월 29일 15:19:31 KST의 과거 500 응답이다. 중복 가입 자체는 정상 검증 결과다. 백엔드 `62db96cd` / PR #212·#213에서 사전 중복 검증과 안전한 안내를 추가했고, 운영 배포 `36573429365`와 이후 최신 운영 배포 `36736886118` 성공을 확인했다. 이번 작업에서 중복 오류를 숨기는 광범위한 Sentry 필터는 추가하지 않았다.

## 수정한 동작

- 알림 드롭다운과 전체 알림 화면이 동일한 선택 훅을 사용한다. 저장된 `/applications/...`를 현재 경로로 바꾸고 query/hash를 보존한다. 외부·프로토콜 상대·잘못된 주소는 열지 않는다.
- 읽음 PATCH를 먼저 완료한 뒤 이동한다. 읽음 요청 대기는 5초로 제한하고 실패해도 상세 이동을 허용한다. 실제 API 실패는 기존 MutationCache에서 계속 Sentry로 수집한다.
- 기다리는 동안 다른 알림을 골랐거나 현재 화면을 떠났으면 늦게 완료된 이전 선택이 화면을 덮지 않는다.
- 서버의 307 리다이렉트로 과거 푸시·공유 링크와 구버전 앱의 직접 진입도 현재 경로로 연결한다.
- 신청 상세의 로그인 returnUrl에는 유효한 `view=sent|received`를 보존한다.

## 검증

- Node 회귀 테스트 150개 통과. 실제 설치된 Axios의 PATCH 응답 완료 전에는 이동하지 않는 HTTP 테스트, 읽음 실패 후 이동, 빠른 연속 선택, 화면 이동·unmount 후 늦은 이동 방지, 정상/옛/잘못된 주소를 포함한다.
- 변경 파일 ESLint, TypeScript 검사, production build 통과. 기존 `.next` 타입 생성 파일이 폐기된 grade-policy 페이지를 참조해 첫 타입 검사가 실패했고, 생성 파일을 임시 폴더로 보관한 뒤 현재 코드로 재생성하여 통과했다. 소스 오류를 무시하는 설정은 추가하지 않았다.
- production 서버를 로컬 3018에 실행하여 옛 상세·편집·목록 주소의 307 및 query 보존을 확인했다. 실제 보호된 상세 화면은 비인증 상태에서 정상 로그인 안내로 연결됐다.
- 운영·개발 API `/api/health` 및 `/api/v2/adoption`은 각각 200, 정확한 웹 origin에 대한 CORS 응답도 확인했다. 처음 잘못 조회한 `/api/v2/health`의 404를 정상 health 경로와 혼동하지 않는다.
- 이 검증은 실제 iPhone에서 같은 알림을 다시 눌러 전송 중단이 사라졌다는 관찰이나 장기간 오류 0건을 뜻하지 않는다. Sentry의 여러 원인을 묶은 Network Error 그룹 전체를 해결 처리하지 않았다.

배포 완료 여부는 해당 커밋의 GitHub 배포 상태와 dev/main 공개 응답으로 별도 확인한다. 사용자 정보·이메일·토큰·심사용 비밀번호는 이 문서에 넣지 않는다.
