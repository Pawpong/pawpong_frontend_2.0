# 전화 인증 반복 실패 후 이메일 인증

- 전화번호 인증의 실제 발송/확인 요청이 두 번 실패하면 이메일 전환을 안내한다. 빈 입력, 성공 요청은 실패로 세지 않는다.
- 기존 계정 정보 단계와 Input/Button/도트 제목/포퐁 색상을 재사용한다. 공통 디자인 및 결제/게임 기능은 변경하지 않는다.
- 이메일 전환 지원은 실제 BE `GET /api/v2/auth/email/config`로 확인한다. 구 서버의404 또는 일시 장애를 성공으로 표시하지 않는다.
- 기본 이메일은 소셜 세션 값이다. 이메일 경로에서는 수신 가능한 주소를 선택할 수 있고, 이 주소를 실제로 인증하여 가입 이메일로 보낸다. 소셜 ID 연결은 유지한다.
- send-code/verify-code 계약은 BE `.kiro/specs/signup-email-fallback`과 동일하다. 코드5분/재전송60초/proof30분이며 서버시간 차이를 반영한다.
- 이메일 검증 성공도 `phoneVerified`를 true로 만들지 않는다. 가입에는 `verificationMethod:email`과 서버 proof를 보내고 미인증 전화번호를 보내지 않는다.
- 다른 이메일, 다른 가입 세션, 방법 변경 이후의 늦은 응답은 인증 상태에 반영하지 않는다. 진행 중 중복 클릭을 막고 API가 실제 성공한 경우에만 완료 표시한다.
- OTP 원문은 저장하지 않는다. 현재 탭의 소셜 가입 세션과 결합된 만료 있는 proof만 sessionStorage에 유지한다. 서버가 최종 권위이며 만료된 이메일 인증은 새로고침 시 계정 정보 단계로 돌아간다.
- 인증 만료/실패/재전송/브리더 및 일반 가입/다른 세션/주소 변경/새로고침을 검증하고 390/768/1440 폭에서44px 입력/버튼, 키보드, 안내 메시지를 확인한다.
- SMTP 실제 인증/전달과 격리 fixture를 구분해 보고한다. dev 검증·병합 후 운영 적용은 별도 사용자 지시까지 보류한다.
