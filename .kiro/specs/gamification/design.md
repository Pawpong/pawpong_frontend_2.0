### 제품 원칙

1. EXP는 **서비스 활동의 누적 기록**이고 레벨은 그 기록의 단계다. 브리더 검증 상태, 동물의 건강·복지, 거래 안전성, 요금제, 인기 순위를 보증하지 않는다.
2. 업적 배지는 확인 가능한 **완료 사건**에 부여한다. 사용자가 점수나 달성 여부를 직접 제출하는 API는 두지 않는다.
3. 단계 명칭은 역할과 무관한 중립 용어를 쓴다. 6월 초안의 `엘리트 브리더`는 폐기된 `New/Elite` 등급과 충돌하므로 채택하지 않는다.
4. 점수나 배지 때문에 입양 신청·상담·게시글 도배, 성급한 입양 완료, 확인되지 않은 건강 정보 작성을 유도하지 않는다.
5. 실제 신청·완료 상태가 권위 있는 원천이다. 신고 **접수**만으로 점수를 차감하거나 배지를 회수하지 않는다.

## 2. 사용자에게 보이는 제도

### 활동 레벨

6월 초안의 임계값을 **검토용 기본안**으로 두되, 명칭과 최상위 조건은 아래처럼 조정한다. E~A는 누적 유효 EXP로 자동 계산하고, S는 임계값과 운영 검수를 모두 충족해야 표시한다. 임계값 미확정 시 전체 레벨 기능을 꺼 둔다.

| 단계 | 누적 유효 EXP 초안 | 공통 명칭 제안 | 승급 |
| --- | ---: | --- | --- |
| E | 0 | 새내기 | 가입 후 시작 |
| D | 500 | 탐험가 | 자동 |
| C | 1,500 | 개척자 | 자동 |
| B | 3,000 | 길잡이 | 자동 |
| A | 6,000 | 선구자 | 자동 |
| S | 10,000 | 동행자 | 운영 검수 후 표시 |

화면에는 `활동 레벨`, 현재/다음 임계값, 최근 적립 사유를 보여준다. 브리더 카드에서 레벨만으로 정렬하거나 `인증 브리더`와 같은 신뢰 문구를 붙이지 않는다. 검증 상태가 필요할 때는 별도의 사실 표시를 쓴다. 레벨 혜택, 검색 가중치, 금전 보상은 이 설계의 v1 범위에서 제외한다.

### 업적 배지

배지는 **획득**, **대표 표시**, **상세 사유**를 구분한다. 처음에는 사건을 확인할 수 있는 업적만 제공한다. 아래 이름과 문구는 카피 검토안이며 별도 배지 원본 목록이 확인되지 않아 확정 카탈로그로 취급하지 않는다.

| 배지 제안 | 대상 | 서버 달성 근거 | 초기 출시 판단 |
| --- | --- | --- | --- |
| 첫걸음 | 양쪽 | 역할별 온보딩 필수 항목 완료 | 필수 항목 정의 후 |
| 첫 기록 | 입양자 | 공개 커뮤니티 첫 글 정상 게시, 최소 내용 조건 충족 | 가능 |
| 첫 분양 소개 | 브리더 | 승인된 계정의 첫 정상 공개 분양글 | 가능. 임시저장·숨김 제외 |
| 이야기 나눔 | 양쪽 | 유효한 후기 첫 작성/수령 | 후기 상태·신고 처리 확인 후 |
| 함께한 입양 | 양쪽 | 브리더 완료 처리와 입양자 확인이 모두 완료된 건 | **입양자 확인 흐름 구현 후** |
| 명예의 전당 TOP 3 | 양쪽 | 콘테스트 `ended` 확정 결과 TOP 3 | 결과 확정 시점에 지급, 취소/정정 처리 필요 |
| 한 달 뒤 소식 | 입양자 | 입양 30일 이후 같은 건의 후속 근황 | 해당 기능 구현 후 |

내 프로필의 배지함은 `획득/미획득`, 획득일, 달성 기준, 진행 상태를 제공한다. 공개 프로필에는 사용자가 고른 **대표 배지 최대 3개**만 보인다. 회수·숨김된 배지나 삭제된 계정의 배지는 노출하지 않는다. 아직 획득하지 못한 배지를 공개 프로필에 미리 표시하지 않는다.

### 애정도

채팅방의 `AffectionBadge`는 상대와의 관계 점수처럼 읽힐 수 있지만 근거 데이터와 동의 범위가 없다. 계정 전체 EXP/업적과 결합하지 않고 보류한다. 향후 관계형 기능을 기획할 경우 관계 양쪽의 공개 동의와 차단·방 삭제 정책을 별도로 정의한다.

## 3. EXP 적립 규칙 초안

아래 수치는 6월 기획의 제안값이다. **운영 승인 전에는 적립 이벤트를 발행하지 않는다.** 먼저 원천 상태와 중복·취소 규칙을 확정한다.

| 영역 | 입양자 초안 | 브리더 초안 | 지급 시점/제약 |
| --- | --- | --- | --- |
| 온보딩 | 프로필 +300, 첫 유효 커뮤니티 글 +200 | 승인 +150, 프로필 +150, 첫 충분한 분양글 +200 | 역할별 최초 1회. `충분한 분양글`의 90% 기준은 필드 목록과 측정식 확정 필요 |
| 반복 커뮤니티 | 글·댓글 각각 +5 | 정보글 +10, 3개 작성 보너스 +50 | 입양자 글/댓글 각각 일 5개, 합산 일 +50·월 +800 제안. 브리더 보너스의 중복·월 상한 확정 필요 |
| 관심 저장 | 저장/팔로우 +1 | — | 입양자 합산 일 +5. 해제→재저장 시 재지급 없음 |
| 상담 | — | 첫 응답 +10, 평가에 따라 완료 건 최종 10/30/50 | 실제 신규 상담 및 유효 응답만. 완료는 기본+보너스 합산이 아니라 **최종 점수**. 평가 UI 구현 전 완료 평가는 적립 보류 |
| 분양글 정보 | — | 기본·건강·부모·환경 각 +25 | 글당 최대 +100, 게시·검증 후 섹션별 최초 1회. 첫 글 온보딩 +200과 이중 지급 금지 |
| 입양 완료 | +500 | +200 | 양측 상태 확인 후 입양 건당 1회. 현재 한쪽 완료 처리만으로는 지급하지 않음 |
| 후기/근황 | 후기 +250, 30일 근황 +250 | 정상 후기 수령 +100 | 입양 건당 1회, 숨김·허위 확인 후 반영 및 회수 |
| 콘테스트 | 출품 +100/주, 투표 +100/주, TOP3 +300/월 | 동일 조건 적용 여부 결정 필요 | 출품/투표 취소 후 재참여로 중복 지급 없음. TOP3는 `ended` 결과만, 콘텐츠 전체 주 +500 제안 |
| 운영 선정 | — | 월간 우수 운영 +200 | 운영 기준·심사 이력 공개 수준 확정 전 보류 |

특히 `입양 신청서 +50`은 6월 문서에도 **신청 건당 또는 최초 1회 미확정**이다. v1에서는 점수를 붙이지 않는다. 신청 자체에 점수를 주면 무분별한 신청을 부추길 수 있다. 단순 로그인, 조회수, 채팅 메시지 수, 신고 없음, 결제/요금제, 앱 재실행에는 점수를 지급하지 않는다.

## 4. 서버 데이터와 이벤트 계약

백엔드의 독립 `gamification` 도메인에 다음을 둔다. 기존 `adopter.bpm`/`breeder.bpm`은 변경하지 않는다.

| 저장 단위 | 필수 필드/제약 |
| --- | --- |
| `exp_ledger` | `ownerModel`, `ownerId`, `ruleKey`, `sourceType`, `sourceId`, `delta`, `policyVersion`, `occurredAt`, `awardedAt`, `reversedAt`, `reversalReason`. 지급과 회수는 감사 가능한 원장 기록. 동일 사건·규칙 유니크 키 |
| `exp_progress` | `(ownerModel, ownerId)` 유니크, `validTotal`, `level`, `policyVersion`, `updatedAt`. 원장 재계산이 가능한 조회용 투영 |
| `badge_catalog` | 안정적인 `key`, 역할 적용 범위, 설명/달성 조건 버전, SVG/아이콘 자산, 공개 여부, 운영 시작/종료일 |
| `badge_award` | 소유자, `badgeKey`, 근거 사건, 획득일, 회수일/사유. 동일 배지 정책에 맞는 유니크 제약 |
| `badge_display` | 소유자별 최대 3개의 획득 배지 키와 순서. 획득 취소 시 표시 목록에서도 제거 |

획득은 **서버의 확정 도메인 사건**에서만 시작한다. 각 사건에는 변경 불가능한 `eventId`, 원천 ID/버전, 수혜자 역할·ID, 발생 시각이 있어야 한다. 동일 사건 재전달, 요청 재시도, 운영 재처리는 원장 유니크 키로 한 번만 반영한다. 일/월/주간 상한은 `Asia/Seoul` 경계로 계산하고, 중복 검사와 잔여 상한 차감은 같은 트랜잭션에서 처리한다. 순위 확정/입양 완료처럼 다중 문서에 의존하는 사건은 **원천의 최종 상태**를 다시 확인한다.

```
원천 상태 확정 → 불변 사건 기록 → 규칙 버전·중복·상한 검사
             → EXP 원장/배지 획득 원자적 기록 → 진행도 투영
             → 내 프로필 조회 / 공개 대표 배지 조회
```

숨김·삭제·입양 취소·콘테스트 결과 정정이 원천 자격을 무효화하면 원 지급을 참조하는 **회수 기록**을 남기고 `validTotal`과 레벨을 재계산한다. 운영자 확정 위반은 사유와 증거 ID를 기록해 검토한다. 6월의 `90일 내 확정 위반 3회 → 한 단계 하락`은 운영 제재 정책 검토안으로 분리한다. 단순 신고 수만으로 차감하지 않는다. 유저의 영구삭제는 원장·배지·투영·표시 설정을 계정 삭제 작업에 포함하되, 법정 보존 대상은 별도 정책에 따른다. 이의제기와 운영 정정은 원장 이력을 남긴다.

### API 계약 제안

기존 백엔드의 `{ success, data }` 응답 봉투, JWT 소유권 검사, 공개 프로필의 최소 필드 원칙을 따른다.

| 경로 | 내용 |
| --- | --- |
| `GET /api/v2/gamification/me` | 내 유효 EXP, 단계, 다음 임계값, 획득 배지, 최근 적립/회수 사유 |
| `GET /api/v2/gamification/users/{userId}` | 공개 단계·대표 배지만. 원장/제재 사유/비공개 활동은 반환하지 않음 |
| `PATCH /api/v2/gamification/me/display-badges` | 소유자가 획득한 공개 배지 키 최대 3개만 선택 |
| `GET /api/v2/gamification/catalog` | 공개 카탈로그와 달성 기준, 정책 버전 |
| 관리자: 정책 미리보기·배지/EXP 수동 정정·최상위 검수 | 관리자 권한, 변경 사유 필수, 감사 로그, 건별 재계산. 대량 변경은 사전 시뮬레이션 |

레벨과 배지는 서버가 계산해 내려준다. 웹/RN은 점수 산식을 복제하지 않는다. 공개 API는 권위 있는 프로필이 아닌 단순 참여 지표라는 설명을 함께 제공한다.

## 5. 웹·RN·어드민 화면

- **웹**: 내 홈 프로필의 `활동 기록` 진입 → 진행도/다음 단계/배지함/이력. 공개 프로필에는 단계와 대표 배지 최대 3개만. 레벨 색과 텍스트를 함께 사용하고 키보드·스크린리더에 획득 조건을 노출한다. 기존 `Badge` 상태 칩, `RankBadgeIcon`의 콘테스트 1~3위, 프로필 활동 배지는 코드와 디자인에서 분리한다.
- **RN**: 현재 WebView 안에서 동일 웹 화면과 API를 사용하므로 점수표·설명·배지 SVG는 웹 배포로 갱신한다. 앱 아이콘/스플래시·OS 권한·딥링크 규격을 바꾸지 않는 범위라면 바이너리 업데이트가 필요 없다. 앱 푸시로 레벨업을 알리려면 추후 알림 동의·빈도 정책을 먼저 정한다.
- **어드민**: 정책 버전/활성화일, 카탈로그, 특정 사용자의 원장·근거 사건, 정정·회수, S 검수, 시뮬레이션 결과, 이상 적립 탐지. 운영자가 사용자의 임의 EXP 값을 바로 덮어쓰는 UI 대신 사유가 남는 조정 사건을 등록한다.
- **노출 제어**: 서버의 `gamification.enabled`와 웹의 표시 플래그를 함께 사용한다. 데이터 복원/적립 검증 기간에는 읽기·쓰기/공개를 각각 제어하고, 준비되지 않은 사용자에게 빈 `0 EXP`를 보이지 않는다.

## 6. 구현 순서와 검증 관문

1. **기획 확정**: 명칭·임계값·행동별 점수·원천의 확정 상태·취소/회수·S 심사 기준을 정책 버전 1로 승인한다. `BPM`의 별도 의미도 정의하거나 UI에서 계속 숨긴다.
2. **백엔드 읽기 기반**: 원장/투영/카탈로그/대표 배지 스키마와 조회 API를 만든다. 기존 계정·영구삭제 계약을 보존한다. 실제 점수 지급은 플래그로 차단한다.
3. **정확성 기반**: 최초 온보딩·유효한 게시·확정 콘테스트 같은 사건부터 연결한다. 과거 데이터 재처리는 원천 상태와 중복 키를 적용한 시뮬레이션→샘플 검토→배치 실행 순서로 한다.
4. **어드민과 웹**: 조회/정정/감사 화면, 내 홈·공개 홈·배지함을 연결한다. RN은 WebView 동작을 iOS/Android에서 확인한다.
5. **단계적 공개**: 내부 계정 → 소규모 집단 → 전체. 부당 적립률, 정정/회수 건수, 도배·무분별한 신청, API 지연, 계정 삭제 누락을 모니터링하고 플래그로 즉시 중단할 수 있게 한다.

필수 회귀 검증: 동일 사건 중복·동시 전달·취소 후 재시도, KST 자정/월말 상한, 첫 분양글 온보딩과 섹션 점수 이중 지급, 콘테스트 종료 전후와 투표 취소, 입양 취소/중복 완료, 신고만 접수된 경우의 무차감, 숨김/삭제 후 회수, 대표 배지 권한, 계정 영구삭제, 구버전 WebView에서 새 필드 무시.

## 7. 정책 확정이 필요한 네 가지 결정

| 결정 | 권장안 |
| --- | --- |
| 레벨 임계값과 이름 | 6월 초안의 `0/500/1,500/3,000/6,000/10,000`을 검토 기준으로 유지하되 역할 공통 명칭으로 교체. 브리더 `New/Elite` 용어는 재사용하지 않음 |
| 점수표 | 먼저 사건 확인 가능한 규칙만 출시. 신청 자체·평가 미구현 상담·입양자 확인 없는 완료 보상은 보류 |
| 최상위 S와 회수 | 10,000 EXP 후 운영 검수, 정확한 검수 기준과 이의제기 절차 승인. 확정 위반만 제재 |
| BPM | 현행 필드의 의미가 없으므로 EXP와 합치지 않음. 별도 지표로 기획하거나 화면에서 계속 비노출 |

이 네 가지가 확정되기 전에는 점수/배지의 실제 적립과 공개 노출을 시작하지 않는다.
