# 포퐁 EXP·업적 배지 재설계안

상태: **기획 검토안 — 서비스 미구현**

작성: 2026-09-26

## 1. 현재 정책과 설계 경계

브리더 `New/Elite` 등급과 예전 활동 레벨 UI는 폐기된 기능이다. 이 문서는 이를 복원하거나 이름만 바꿔 재도입하지 않는다. [현재 정책](../../../docs/design.md)은 EXP의 산식·단계·혜택이 확정되지 않아 EXP/BPM을 등급의 대체물로 노출하지 않도록 한다. 2026-06-04 Obsidian의 `포퐁_EXP_레벨_뱃지_정책_v2.md`는 초안이며, E~S 단계와 행동별 점수는 현행 정책이 아니다.

이번 설계의 제품 단위는 **검증된 활동 → 포퐁 EXP → 개별 업적 배지**다. EXP는 실제 서비스 참여를 기록하는 수치다. 배지는 특정 행동의 완료를 설명하는 수집형 기록이다. 계정에 단일 레벨·티어·칭호를 부여하지 않고, EXP 총량으로 브리더 신뢰도나 입양 적합도를 판단하지 않는다. 브리더 인증 상태와 요금제는 완전히 별도다. 기존 `bpm` 필드는 의미가 확정되지 않았으므로 EXP로 바꾸거나 UI에 재노출하지 않는다.

## 2. 사용자가 경험할 흐름

1. 회원이 실제로 활동하면 서버가 확정된 행동을 확인하고 해당 영역의 EXP를 한 번 지급한다.
2. 내 `포퐁 활동` 화면에는 총 EXP, 활동별 적립 이력, 업적별 진행 조건이 표시된다. 운영 플래그를 켜기 전에는 이 화면과 적립을 모두 숨긴다.
3. 배지 조건을 채우면 서버가 배지를 지급하고, 배지함에서 이름·획득일·달성 근거를 볼 수 있다. 축하 알림은 기존 알림 동의와 빈도 정책이 준비된 뒤 연결한다.
4. 회원은 획득한 배지 중 최대 3개를 대표 배지로 고른다. 공개 프로필에는 대표 배지와 객관적인 달성 설명만 표시한다. 총 EXP나 개인 이력은 기본적으로 비공개다.

EXP는 구매·현금 전환·검색 순위·서비스 권한과 연결하지 않는다. `EXP 상위 브리더`, `우수 입양자`처럼 안전성이나 품질을 보증하는 문구도 사용하지 않는다. 웹뷰 앱은 같은 웹 화면/API를 쓰므로 배지 카탈로그와 설명은 웹 배포로 갱신한다.

## 3. EXP 원칙과 적립안

EXP는 **행동별 고정 점수**로 계산한다. 무제한 반복 행동보다 검증 가능한 첫 완료·지속 활동에 무게를 둔다. 아래 수치는 새 검토안이며 6월 초안의 점수를 그대로 승계하지 않는다. 원천 사건·상한·취소 규칙이 확정되기 전에는 지급하지 않는다.

| 영역 | 유효 사건 | EXP 제안 | 상한·악용 방지 |
| --- | --- | ---: | --- |
| 시작 | 역할별 필수 프로필 완료 | 100 | 계정·역할당 1회, 필수 필드 정의 필요 |
| 커뮤니티 | 정상 공개 게시글 | 20 | 일 2건·월 20건, 최소 내용·중복·숨김 검사 |
| 커뮤니티 | 정상 공개 댓글 | 5 | 일 5건·월 50건, 본인 글 반복·삭제 재작성 제외 |
| 입양 정보 | 승인된 브리더의 정상 공개 분양글 | 50 | 반려동물·공고당 1회, 임시저장/중복 공고 제외 |
| 상담 | 양측의 유효한 첫 상담 응답 | 양측 각 20 | 상담 건당 1회, 자동 메시지·자기 계정 간 대화 제외 |
| 입양 완료 | 양측이 같은 입양 건을 확인 | 양측 각 200 | 입양 건당 1회, 현재 양측 확인 흐름 구현 전 보류 |
| 후기 | 입양 건에 연결된 정상 공개 후기 | 작성자 50 | 입양 건당 1회, 허위·삭제·숨김 시 회수 |
| 콘테스트 | 확정된 출품 | 30 | 대회당 1회, 취소 후 재출품 재지급 없음 |
| 콘테스트 | 최종 TOP 3 확정 | 50 | 대회당 1회, 결과 정정 시 회수 |

단순 로그인, 조회수, 무제한 좋아요·팔로우, 채팅 메시지 수, 입양 **신청 자체**, 결제, 신고 없음, 앱 재실행에는 EXP를 주지 않는다. 가입/게시/상담이 취소되거나 허위로 확정되면 원 지급을 참조해 회수한다. 신고 접수만으로는 회수하지 않는다. 일·월 상한은 `Asia/Seoul` 기준으로 집계한다. 점수와 상한은 운영 시뮬레이션 후 확정하고 `policyVersion`으로 보존한다.

## 4. 업적 배지 카탈로그 초안

배지는 **사건 기반**이다. 총 EXP만 쌓였다는 이유로 일괄 승급시키지 않는다. 따라서 배지는 활동 유형을 설명하고, 한 사람이 여러 종류를 수집할 수 있다. 동일한 배지는 계정에 한 번만 지급하며, 조건이 반복형이면 배지 이름과 기준을 별도 버전으로 정의한다.

| 배지 | 대상 | 획득 조건 | 출시 조건 |
| --- | --- | --- | --- |
| 첫발자국 | 양쪽 | 역할별 필수 프로필 완료 및 시작 EXP 지급 | 필수 프로필 기준 확정 |
| 첫 이야기 | 양쪽 | 정상 공개 커뮤니티 첫 글과 해당 EXP 지급 | 게시글 유효성 판정 |
| 이야기 잇기 | 양쪽 | 서로 다른 정상 글에 유효 댓글 10개와 해당 EXP 지급 | 자기 글·도배 제외 규칙 |
| 첫 소개 | 브리더 | 승인된 계정의 정상 공개 분양글 첫 건과 해당 EXP 지급 | 승인·공고 상태 확정 |
| 첫 상담 | 양쪽 | 양측 유효 첫 상담 응답과 해당 EXP 지급 | 상담 원천 사건 확정 |
| 함께한 입양 | 양쪽 | 동일 입양 건을 양측이 완료 확인하고 EXP 지급 | 양측 확인 흐름 구현 후 |
| 후기의 시작 | 입양자 | 정상 공개 첫 후기와 해당 EXP 지급 | 후기의 입양 건 연결 확인 |
| 무대에 서다 | 양쪽 | 확정된 콘테스트 첫 출품과 해당 EXP 지급 | 결과 취소·정정 정책 |
| 명예의 전당 | 양쪽 | 콘테스트 최종 TOP 3 확정 | 종료 결과를 권위 있는 원천으로 사용 |

배지는 **획득 조건**, **현재 진행도**, **획득/회수 상태**를 분리한다. 예를 들어 `이야기 잇기`는 `유효 댓글 6/10`처럼 진행을 보여주지만, 전체 EXP가 높아도 댓글 조건이 없으면 지급하지 않는다. 배지 SVG는 카탈로그 키에 연결하고, SVG가 없어도 이름·설명으로 접근 가능하게 한다. 배지 획득은 브리더 자격 인증이나 입양 안전 보증으로 해석되지 않도록 설명한다.

## 5. 서버·어드민 계약

백엔드는 기존 프로필 `bpm`을 건드리지 않고 별도 `gamification` 도메인을 둔다.

| 저장 단위 | 필수 내용 |
| --- | --- |
| `activity_event` | 불변 `eventId`, 사건 종류/원천 ID·버전, 수혜자 역할·ID, 확정 시각. 재전달에도 한 번만 처리 |
| `exp_ledger` | 사건 ID, 규칙 키·버전, `delta`, 지급/회수 시각·사유. 수정·삭제 대신 역분개 기록 |
| `exp_summary` | 소유자별 유효 합계와 활동별 합계. 원장으로 재계산 가능한 조회용 투영 |
| `badge_catalog` | 안정적 키, 표시 이름·설명, 조건 버전, SVG 경로, 공개·활성 상태 |
| `badge_award` | 소유자·배지 키·근거 사건, 획득·회수 시각, 유니크 제약 |
| `badge_display` | 소유자별 획득 배지 최대 3개의 순서. 회수 시 자동 제거 |

원천 사건 확정 → 유효성·상한·중복 검사 → EXP 원장 기록 → 배지 조건 재평가 → 투영 갱신 순서로 처리한다. 같은 사건의 중복 전달, 동시 요청, 취소 후 재시도에도 중복 지급되지 않아야 한다. 운영 정정은 원장을 직접 덮어쓰지 않고 사유·담당자·근거가 남는 조정 사건으로 기록한다. 계정 영구삭제 시 원장·배지·표시 설정은 기존 삭제 정책에 포함하고, 법정 보존 대상은 별도 정책에 따른다.

| API 제안 | 응답·권한 |
| --- | --- |
| `GET /api/v2/gamification/me` | 본인 총/영역별 EXP, 최근 내역, 배지와 진행도 |
| `GET /api/v2/gamification/catalog` | 공개 배지 이름·SVG·달성 기준·정책 버전 |
| `GET /api/v2/gamification/users/{userId}` | 공개 대표 배지 최대 3개. EXP 원장·비공개 이력 제외 |
| `PATCH /api/v2/gamification/me/display-badges` | 본인이 획득한 공개 배지만 선택, 최대 3개 |

어드민에는 정책 버전/적용일, 사건·원장·배지 조회, 지급 시뮬레이션, 수동 정정·회수와 감사 로그, 비정상 반복 적립 탐지를 둔다. 게시글 삭제·상담 무효·입양 취소·콘테스트 결과 정정 시 관련 지급과 배지가 어떻게 바뀌는지 운영자가 확인할 수 있어야 한다. 어드민에서 점수나 배지를 임의로 덮어쓰는 기능은 두지 않는다.

## 6. 적용 순서와 검증

1. 기획에서 행동 정의, 점수·상한, 배지 이름·SVG, 취소·회수 조건을 승인한다. **레벨·티어·칭호는 출시 항목에 넣지 않는다.**
2. 백엔드 사건/원장/배지 카탈로그와 어드민 조회·정정을 만들고, 플래그를 끈 상태에서 과거 사건 재처리를 시뮬레이션한다.
3. 시작·게시·콘테스트처럼 현재 원천 상태가 명확한 사건부터 연결한다. 상담·입양 완료는 양측 확인 상태가 구현된 뒤 연결한다.
4. 웹의 내 활동·배지함·대표 배지를 연결한다. RN iOS/Android WebView에서 구버전 앱 포함 표시·접근성·로그인 세션을 확인한다.
5. 내부 계정→소규모 공개→전체 공개로 확대한다. 부당 적립·회수·API 지연·영구삭제 누락을 모니터링하고 플래그로 즉시 중단한다.

필수 검증: 같은 사건의 중복·동시 전달, KST 자정/월말 상한, 숨김/삭제 후 회수, 신고 접수만 된 상태의 무차감, 배지 진행도와 지급 조건 일치, 대표 배지 권한, 계정 영구삭제, 구버전 WebView에서 새 필드 무시.

현재 서비스에는 EXP 적립과 업적 배지 화면을 켜지 않는다. 숫자·조건·카피가 승인된 정책 버전으로 고정되고 실제 사건으로 검증된 뒤에만 공개한다.
