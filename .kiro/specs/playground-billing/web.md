# 놀이터 결제 웹 연결

서버 카탈로그로 충전형·구독형·비소모성 상품을 관리하고, RN 공통 브리지로 스토어 가격 조회와 결제를 수행한다. 첫 소비 기능은 `ai_image`, 기본 공통 이용권 풀은 `playground`다. 실제 상품 코드·수량·가격은 미정이며 샘플 상품을 운영에 등록하거나 판매를 활성화하지 않는다.

## 연결 계약

백엔드 `iap-purchase-api/.kiro/specs/in-app-purchase/api-contract.md`와 합의한 `/api/v2/iap/products`, `/policy`, `/account`, `/purchases`, `/purchases/verify`를 사용한다. 키·가격·지급 수량은 웹에서 서버에 보내지 않는다. 회원별 고정 `accountToken`은 스토어 구매에만 사용한다.

- `/playground`: 기능 진입, 무료/유료 이용권, 충전·구독, 구매 복원·관리와 구매 내역.
- `/ai-filter`: 서버 Account의 무료 잔량과 이용권 잔액/비용으로 이용 가능한 횟수를 표시한다. 보관함 개수로 쿼터를 계산하지 않는다.
- 신규 앱의 `inAppPurchase` capability와 명시적인 iOS/Android platform이 있을 때만 스토어 상품을 조회한다. 일반 브라우저와 구버전 앱에는 구매 버튼을 제공하지 않는다.
- iOS는 실제 구독 기간이 있는 상품, Android는 가격 단계와 구매 offerToken이 함께 있는 요금제만 판매한다. 대표 가격을 다른 요금제에 적용하지 않는다.
- 로그인 후, 놀이터 진입, 앱 복귀 시 미완료 거래를 재검증한다. 승인 대기·오류에서는 종료하지 않는다. 서버가 `finishable=true`를 확인한 뒤에만 RN 원래 거래 ID로 finish한다.
- 로그아웃/계정 전환 이후 늦은 응답을 처리하지 않으며 영수증을 저장소·분석 로그에 기록하지 않는다. 검증 mutation은 시작 계정 토큰을 고정하고 401 자동 재전송을 하지 않는다. 최종 소유권 검증은 서버 영수증의 accountToken으로 수행한다.
- API 장애나 설정 미완료를 구매 성공으로 처리하지 않는다. 상품·잔액 조회 실패 시 재시도를 제공한다.

## 검증

- 최신 dev(케어맵·AI 비교 편집 포함) 통합 후 전체 Node 테스트 207개, 타입체크, production build 통과.
- 변경 파일 ESLint 통과. 전체 FSD 검사에는 기존 cross-import/public API 규칙 위반과 slice 수 경고가 남아 있으며 결제 슬라이스 cross-import는 없다.
- Orca 브라우저에서 `iap.localhost:3023` → 실제 Nest API → 격리 MongoMemoryReplSet으로 카탈로그·계정·구매·원장 흐름을 확인했다. 외부 스토어와 RN 응답 경계만 테스트 fixture로 대체했으며 실제 청구는 없다.
- 취소/승인 대기는 지급 및 finish 없이 유지된다. 충전 5 + 구독 3 = 잔액 8, 중복 복원 후 잔액 8 유지, 관리자 회수 후 3, 재지급 후 8과 감사 이벤트를 확인했다.
- 무료 4/일, 이미지 비용 2 정책 변경 후 AI 화면에 무료 4와 유료 4를 합쳐 이용 가능 8회를 표시했다. 화면 진입/앱 복귀 시 최신 계정 정책을 읽는다.
- 복원 시 인증 쿠키가 없으면 로그인 안내가 표시된다. 결제 직전 계정 조회에서 토큰이 갱신되면 같은 계정인지 확인한 뒤 갱신 토큰을 검증 요청에 고정한다.
- 세션 변경은 결제 작업만 취소하며 페이지를 재마운트하지 않는다. 프로필 조회와 게시글 이탈 확인 후에도 미저장 초안이 유지되는 것을 브라우저에서 확인했다.
- 실제 Apple·Google 샌드박스 결제는 네이티브 새 빌드와 스토어 상품 등록이 필요하다.

## 운영 반영 전

서버 키는 저장소 밖의 개인 설정 디렉터리에만 보관한다. 이번 작업에서 운영 DB·운영 서버를 변경하거나 스토어 심사를 제출하지 않는다. 백엔드 환경 변수 주입, 알림 웹훅/Google PubSub 설정, 실제 스토어 상품 심사 및 샌드박스 구매 확인이 출시 전 남아 있다.
