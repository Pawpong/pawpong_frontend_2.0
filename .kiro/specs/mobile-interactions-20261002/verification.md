# 앱 댓글·채팅·검색·사진 비교 검증 (2026-10-02)

아래는 1차 웹·백엔드 수정 검증 기록임. 이 단계에서는 네이티브/RN 파일을 수정하지 않았음. 이후 알림 권한 조회·설정 열기 RN 코드를 master에 준비했으며 새 앱 빌드는 배포하지 않았음. 후속 알림 안내는 push-guide.md, 원본 비교 공개 선택은 ../ai-community-comparison-20261002/verification.md에 기록함. 배포는 dev 검증 후 main 반영 순서로 진행함.

## 변경 동작

- 댓글 제출을 form submit으로 통일하고 한글 조합 중 Enter·중복 제출을 막음. 처리 중 상태를 표시하고 실패 시 초안과 오류를 남김. 동의 부족 403은 동의 화면으로 안내함. 목록 재조회가 댓글 제출 완료를 지연시키지 않음.
- 새 채팅 메시지를 DB에 저장할 때 푸시 대기 상태도 저장함. 5초 뒤에도 읽지 않았으면 알림함과 기존 FCM 경로로 연결함. 이미 읽은 대화, 차단·정지·닫힌 방, 24시간이 지난 메시지, 과거 대화는 제외함. 임대 선점과 만료 복구, 계정 삭제 쓰기 보호를 적용함.
- 웹의 메시지 GET은 읽음 상태를 바꾸지 않음. 실제로 열린 대화에서 보이는 메시지를 기존 소켓 읽음 처리로 반영함. 기존 클라이언트의 API 기본 동작은 유지함.
- 게시글 댓글·답글·좋아요도 기존 FCM 경로를 이용함. 자기 알림과 동일 수신자 중복은 제외함.
- 닉네임으로 입양자·브리더를 검색하고 선택해 1:1 대화를 시작함. 개인 설정의 검색·새 채팅 허용은 기존 회원도 기본 true임. 검색 거부는 직접 ID로 새 방을 만드는 요청도 막으며 기존 활성 대화는 유지함. 양방향 차단·정지·본인·앱 표시 미동의 작성자는 앱 검색에서 제외하고 연락처는 반환하지 않음.
- 앱에서만, 게시물이 있는 미동의 작성자에게 공개 동의 모달을 안내함. 닫을 수 있으며 화면 이동·앱 복귀 때 재안내함. 체크 후 명시적으로 저장해야 동의가 기록됨. 웹에는 안내 모달을 띄우지 않음.
- AI 보관함에서 비포(원본)·애프터(AI 결과)를 전환함. 원본은 인증한 작업 소유자만 받으며 비교 Blob URL은 닫힐 때 해제함. 저장·커뮤니티 업로드는 결과 사진을 사용함.
- 팔로우 후 프로필 조회가 skipAuth로 익명 처리되어 isFollowing=false가 되던 문제와 입양자 캐시 갱신 누락을 수정함. 실제 팔로우 상태는 팔로잉으로 표시함.
- 탐색 탭은 브리더를 왼쪽, 입양을 오른쪽에 배치함.

## 검증

- Nest HTTP·격리 Mongo replica set 기반 신규 종단간 계약 21개 통과함. 댓글·답글·좋아요 FCM 요청, 중복/읽음/차단/정지/방 종료 제외, 큐 선점과 임대 복구, 검색 기본값/허용 설정/직접 방 요청/정규식 문자/개인정보 최소 반환, 브리더 간 DM, 동의 상태, 팔로우 저장·목록·카운트, 원본 인증·소유권·MIME·바이트를 검증함.
- 채팅·커뮤니티·동의·AI·알림 관련 단위 테스트 102개 통과함.
- 기존 채팅 세션·콘텐츠 권리 계약 10개 통과함.
- 확장한 기존 채팅·커뮤니티·AI 종단간 검사 111개 중 15개는 오래된 테스트 계정에 userRole이 없어 쓰기 보호에서 401이었음. 두 테스트 fixture에 실제 계정 역할을 넣어 재실행한 17개 전부 통과함. 인증이나 쓰기 보호는 완화하지 않았음.
- 프론트 Node 회귀 150개, 변경 TS/TSX ESLint, 양쪽 타입 검사·production build 통과함. 최신 공유 UI 변경을 반영한 뒤 프론트 빌드도 재검사함.
- 신규 백엔드 파일의 InjectModel 위치와 DTO/guard/interceptor 누수 검사에서 위반 없음.
- Orca의 모바일 폭 Chromium 화면과 실제 격리 Nest 서버를 연결해 댓글 저장/입력 초기화, 네트워크 실패 시 초안 보존, 팔로잉 버튼/내 팔로잉 목록, 닉네임 선택→소켓 채팅 저장, 개인정보 설정 재조회 유지, 원본 Blob 이미지 로드→결과 전환, 앱 표시 모달의 웹 제외/닫기/앱 복귀 재안내/명시적 저장을 확인함.

## 검증 범위와 제한

운영 DB에는 테스트 게시물·댓글·채팅을 쓰지 않았음. FCM 및 이미지 저장소는 격리 테스트에서 외부 포트만 대체했으며 실제 HTTP·권한·DB·알림 빌더를 사용했음. 따라서 기기 잠금 화면의 실제 푸시 수신 성공을 뜻하지 않음. FCM 권한·유효 토큰·OS 설정에 따라 기기 수신은 달라짐.

iOS Simulator는 이 호스트 Xcode의 SimulatorKit.framework가 없어 실행되지 않았음. 모바일 폭 Chromium 검증은 WKWebView/실제 iPhone 터치 검증과 다름. 처음 보고된 iPhone의 무반응 댓글 제출은 실기기에서 재현하지 못했으며 배포 후 재확인이 필요함. 푸시는 기존 발송기의 실패 기록 방식을 유지하며 워커 임대 복구의 비정상 종료 경계에서는 중복 전달 가능성이 남음.
