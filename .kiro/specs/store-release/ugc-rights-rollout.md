# 게시물 이용 동의 및 iOS 심사 차단 해소 계획

2026-09-26 확인: 현재 공개 이용약관과 가입 동의 전문에는 회원 게시물의 웹·앱 표시를 포퐁에 허락하는 조항이 없다. 앱은 WebView로 운영 콘텐츠를 표시하므로, Apple의 콘텐츠 권한 질문에서 제3자 콘텐츠가 없다고 답할 수 없다. 기존 게시물이 공개되어 있다는 사실만으로 새 약관에 동의한 것으로 처리하지 않는다.

사용자 결정: 새 조항에 대해 게시자별 재동의를 받고, 동의 전 기존 콘텐츠는 앱에 노출하지 않는다. 이 브랜치의 제5조의2는 **검토용 초안**이다. 서버 약관은 기존 동의 이력을 덮어쓰지 않도록 `2026-10-03` 새 버전으로 분리했고, 시더에는 별도 발행 가드를 추가했다. 약관을 운영에 발행하거나 App Store Connect에서 콘텐츠 권한을 선언하지 않았다.

## 출시 전에 필요한 구현

1. 운영자·법률 검토로 제5조의2 문구, 시행일, 7일 전 공지를 확정한다. 공개 약관, 가입 화면, 서버 활성 약관을 같은 버전으로 맞춘다.
2. 기존 입양자와 브리더가 새 조항을 명시적으로 수락하는 화면과 API를 만든다. 서버는 계정 ID·역할·약관 버전·동의 시각을 기록하고, 동의 이력을 읽을 수 있어야 한다. 거부해도 계정 조회나 삭제 요청을 막지 않는다.
3. 새 글·사진·분양글·브리더 프로필·명예의 전당 응모의 공개/수정 시 최신 권리 동의를 서버에서 확인한다. 업로드 화면에는 본인에게 필요한 권리와 촬영 대상자 동의가 있음을 확인하는 문구를 보여준다. 요청 본문 체크박스만 믿지 않는다.
4. 기존 콘텐츠는 게시자 동의 이력이 확인될 때까지 iOS 앱 조회에서 제외한다. 홈, 탐색, 브리더, 분양, 커뮤니티, 명예의 전당, 상세 URL과 이미지 응답까지 점검한다. 앱과 웹을 구분하는 기준은 서버에서 일관되게 적용해야 하며, 화면 CSS로만 숨기지 않는다.
5. 동의한 게시자 콘텐츠만 앱에서 다시 노출되는지, 동의하지 않은 작성자의 목록·상세·이미지가 앱에서 보이지 않는지 통합 검증한다. 삭제·동의 철회 시의 신규 노출 중단도 확인한다.
6. 실제 콘텐츠와 외부 에셋의 권리 증빙을 확인한 뒤 App Store Connect 콘텐츠 권한을 선언한다. 앱 개인정보 신고와 연령 등급도 별도로 완료해야 심사에 추가할 수 있다.

관리자 홍보 푸시는 서비스 알림과 구분한다. 별도 백엔드·관리자 화면 변경에서는 `marketing` 목적일 때 `marketingAgreed=true` 수신자만 대상에 포함한다. 채팅·신청 상태 알림은 서비스 기능이며, 개인별 게시물 추천은 Apple의 제품 개인 맞춤화 목적을 별도로 검토한다.

이 문서는 심사 제출 완료 증거가 아니다. 운영 동의·콘텐츠 필터·개인정보 방침 정합성이 확인될 때까지 `심사에 추가`를 재시도하지 않는다.
